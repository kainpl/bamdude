# Invariants: Library and model sources

Full text of the rules that [`CLAUDE.md`](../../../CLAUDE.md) keeps in short form, with the reasons and the history behind them. `Vault:` pointers name notes in the maintainer's private knowledge base; everything a contributor needs is here.

## A long walk holds neither the transaction nor the loop (m148)

External-folder scanning lives in `services/library_scan.py`: stat / hash / 3MF parse happen with **no session open** and off the event loop via `to_thread`; writes go in `BATCH_SIZE` chunks, each its own short transaction (sized for *lock time*, not commit cost — WAL + `synchronous=NORMAL` means a commit costs no fsync). Doing it the old way took SQLite's write lock from the first `flush` to the final `commit` with a whole NAS walk in between, and unrelated queries died with `database is locked` naming an innocent victim. ⚠️ **Therefore the request cannot wait for the result** — `POST /library/folders/{id}/scan` answers `202 {job_id}`, never counts; progress rides the socket, the summary is the `library_scan_jobs` row. ⚠️ **Reachability is checked in the worker, not the handler** (`Path.exists()` blocks on a hung mount). ⚠️ **Short transactions cost the rollback that used to make a failed scan harmless** — so `remove_vanished` refuses every deletion when the walk came back empty against a stocked folder (`EMPTY_WALK_GUARD = 1`, `skipped_deletions=True`, reported on screen): an unreachable share is indistinguishable from a folder somebody emptied. ⚠️ **Ending a scan is TWO halves** — the row *and* the socket; `_fail_job` does both, and the event carries `folder_id` or the strip it should clear cannot be found. ⚠️ FK `ON DELETE CASCADE` on the job rows is honoured by PostgreSQL only — this codebase never sets `PRAGMA foreign_keys = ON`.

## A library file's visibility has one rule, and an ownerless external file is shared (G11); a folder has an owner and one rule too (N56)

`models/library.owner_scope_sees` and its SQL twin `owner_scope_clause` are the rule every reader asks (`_library_file_visible`, `library_file_name_visible`, lists, stats, tag counts, the queue's source check, ingest's dedupe, `live_projection`): a `read_own` caller sees its own files AND files without an owner that live in an external folder — the scanner's rows, which nobody owns. Write and delete did not widen. What `read_own` must not learn is other users' FILES, so folder counters, duplicate counts and the duplicates panel count through the same rule, and a file's satellites — notes (`library_notes`), the user link, photos — resolve the file through it first (hidden, trashed and missing are the same 404). Mounting an external folder is `settings:update` (it names a host directory). `PUT /library/folders/{id}` is the one writer of a folder's parent: missing parent, a move into or out of an external folder, a move into its own subtree are refused with machine codes, decided AFTER the lock (`take_write_lock` on SQLite, the folder rows `FOR NO KEY UPDATE` on PostgreSQL).

**Folders (N56, upstream #3201, owner decisions 2026-11-27).** A folder has an owner (`library_folders.created_by_id`, the actor of the door that made it) and may be `shared` with everyone. `services/library_folder_access.py` is the folders' one rule, as `owner_scope_sees` is the files': every function takes the ACTOR and "sees all" from its door — the library's read routes from `require_ownership_permission`; the write doors (upload, ZIP, slice, assembly, imports, a new folder, an archive saved to the library, a printer's SD import, a product import) from `request_actor` (`acting_user` + `library_name_scope == "all"`, never the archive's `read_all`); a job's actor is captured at accept; Telegram from the chat (its linked user; its group's `library:read_all`; a chat without a user writes only into shared folders and the root). A caller who sees every file sees every folder. A `read_own` caller sees their own folders, shared ones, the folders holding a file the file rule shows them, and the folders above those — for navigation only; any other folder is 404 everywhere it is named (the tree, one folder, its readme, a file list filtered by it, `by-product`, `stats`; the product page lists it `hidden`, without a name). They put files and folders only into their own, shared ones and the root (`can_write_folder`; 404 unseen, 403 only seen) — every door that puts a file into a chosen folder asks it, the Telegram callback asks again because its data comes from the client. A result made from a file (a slice, an assembly, a relayout) goes beside its source only while the actor may still write there, decided when the result is PUBLISHED, else the root (`result_folder_id`; assembly reports `folder_private`). A by-name door (a ZIP's folder and every path segment, the importers' `MakerWorld` / `Manyfold`, a product import's folder, `Telegram` in the root) goes through ONE helper, `writable_folder_named` — two folders of one name under one parent are normal now, so ⚠️ never `scalar_one_or_none()` by name; a system folder answers only with a shared one and is created shared and ownerless. Renaming and moving: `library:update_all`, or the owner with `update_own`; sharing the same (owner decision D3, upstream lets only `update_all`); product links stay `update_all`'s. An external folder and its subfolders are shared and ownerless, and stay so: "private" would hide nothing, since their ownerless files are everyone's by the file rule (`folder_external_shared`). Deleting: `delete_all` anything; with `delete_own` the owner deletes a folder when everything under it — folders and files, trashed ones too — is theirs, nothing external and nothing linked to a product; an ownerless folder only when truly empty (#1781). m268 settled the existing folders once, in its `upgrade` only when `shared` was just added (a DEBUG `replay` adds columns and touches no row): a folder whose files all the way down belong to one user became that user's, an empty folder inside it went with it, every other folder became shared — empty, several owners, ownerless files, external, linked to a product, a Virtual Printer's target, the root `MakerWorld` / `Manyfold` / `Telegram`. A deleted user's folders lose their owner (`detach_account_rows`, `content_delete_user_reference_policy.json`), `shared` stays. Guards: `tests/integration/test_library_folder_ownership.py`, `tests/unit/services/test_library_folder_access.py`, `tests/unit/test_migration_m268.py`. Vault: `40-invariants/inv-library-visibility-has-one-rule.md`.

## A library file's photos have one writer and leave the disk after the commit (G11, m233)

`services/library_file_photos.py` alone writes `library_file_photos` and the files under `<library>/photos/<file id>/` (guard test); a photo is never stored as sent (re-encoded, orientation applied, metadata dropped — the part-photo helper); the two picture routes sit under the MEDIA token and check the PARENT file. Photos belong to the file row: they do not travel to archives, and another row with the same hash does not show them. Every path that purges a library file calls `forget_files` (an AST guard fails a function that calls `purge_file_product_links` without it), and the files are removed only after the purge's commit — a rollback keeps rows and pictures, an unknown commit outcome deletes nothing. `scripts/prune_orphan_archive_files.py` takes the live photo paths from the table. A rename or move on an external share keeps the row (`library_scan`: exactly one vanished row and one new path with the same valid hash in one mount — anything ambiguous is today's vanish + new file), so notes, photos, tags, product links and queued jobs stay; only the swap declaration is taken again, through `declare_ingest` by the new name, and an operator's declaration is dropped (owner, 2026-11-16). A renamed or moved DIRECTORY keeps its folder row the same way (`library_scan.match_directories`, decided from this scan's file moves: every move out of the old folder names one new directory and every move into that directory names that one old folder; a subfolder nothing spoke of follows a matched parent by name) — so `product_folders`, the standing rule, survives; empty, split and merged directories are never guessed. Vault: `40-invariants/inv-library-file-photos-single-writer.md`.

## A 3D-model site is a `ModelProvider`, and the routes reach it only through one (upstream #2845, 2026-09-25)

`services/model_providers/` holds the interface (`base.py`: a `ModelProvider` descriptor — identity, `host_patterns`, `default_folder_name`, `view_permission` / `import_permission`, `parse_url` / `canonical_url` / `source_url_filter`, the SSRF allowlists `thumbnail_hosts` / `download_hosts` — plus a per-request `ProviderService`: `get_status` / `resolve` / `get_download` / `download` / `fetch_thumbnail` / `close`) and the `registry`; MakerWorld is the first implementation (`makerworld/`, registered on package import). The `/makerworld/*` routes pick the provider through `registry.find_for_url` (resolve) or `registry.get(source_type)` (import — an unknown one is a 400 BEFORE the default folder is created), build ONE service per request via `provider.build_service(db=, user=, api_key_owner=)` and close it once, after the meta row and covers. ⚠️ Every endpoint keeps its own `RequirePermission` (MakerWorld's, read off the descriptor); `routes/makerworld._authorize_for_provider` checks a provider's permission ON TOP when it differs — never upstream's "authentication only" route gate. ⚠️ The Bambu Cloud credential has ONE seam, `services/bambu_cloud_credentials.py` (`get_stored_token`, `is_cloud_token_invalid`, `mark_cloud_token_invalid`, …): services import it, never `api/routes/cloud.py` (`test_services_take_credentials_from_the_seam.py`); sign-in stays in the route; RENEWAL is the seam's (`renew_or_invalidate`, G12): one renewal at a time per credential identity (a waiter re-reads the stored pair and uses it — it never reports "expired" for a sign-in another caller just renewed), one transparent repeat of the request, and a network failure, timeout, 5xx or non-JSON answer NEVER marks a token invalid or clears it — unreachable is a 502, only Bambu's real refusal of the refresh marks the sign-in dead, and `clear_token` runs on logout alone. ⚠️ `makerworld/http.py` sends our honest versioned User-Agent, never upstream's. The old `services/makerworld.py` / `makerworld_meta.py` are gone — m056's import lines were repointed rather than keeping shims (owner's call; `test_makerworld_has_one_home.py`). The second site has arrived (Manyfold, G12): the page is "Model sources" with a tab per provider, `/model-sources/{source}/…` routes carry each provider's OWN permission, and a provider-neutral import record (m235) holds where an import came from; MakerWorld stays on `/makerworld/*` with its meta table (m056) and import history untouched, and its import route never reaches another provider. Vault: `40-invariants/inv-a-model-site-is-a-provider.md`.

## A self-hosted model source is reached through one pinned transport (G12, Manyfold)

A provider whose address an administrator configures (Manyfold) makes EVERY outbound request through `services/model_providers/outbound.py` — the provider package imports no HTTP library (AST guard `test_model_providers_fetch_only_through_the_guard.py`; MakerWorld is the named static-host exception). The transport admits one configured origin (http/https; loopback and private addresses allowed ON PURPOSE — the administrator set it; cloud-metadata, link-local, multicast and every IPv6 form that carries such an address refused; numeric and trailing-dot host spellings normalised or refused in ONE function), resolves a name once, checks EVERY returned address and connects only to a checked one through its own socket layer while the request keeps the host NAME (so pool key, `Host`, SNI and certificate verification are by name). It is built on httpcore's public `network_backend`, proves on first use that connections really pass through that layer and DISABLES ITSELF otherwise (`manyfold_transport_unavailable`) — it fails closed, never falls back to an ordinary client; `requirements.txt` bounds httpx/httpcore to the tested range and names the two tests that must pass before a bound is raised. No redirect is followed except the way to file storage for file and preview bytes (at most `MAX_STORAGE_HOPS`): without the bearer token or cookies — nothing after the request left the origin carries them, not even a redirect back — and under the SAME address rules as the configured origin: http or https, loopback and private allowed, metadata / link-local refused, every resolved address checked and pinned. ⚠️ Never narrow storage to "https only" or "public only": BamDude is a LAN system first and a MinIO beside Manyfold over plain http is the normal topology (owner, 2026-11-17, as upstream). URLs found in the source's answers are never fetched — requests are built from the configured base plus validated ids. Byte caps count the WIRE (`Accept-Encoding: identity`; a compressed answer is refused). The connection is a write-only integration credential (a kept secret with a changed address or client ID is `manyfold_secret_required`), saved and tested by an administrator only. Imports of every model source go through ONE import core (`services/model_import.py`) into the library's ingest door; streamed files are staged under `DATA_DIR/model-imports/` with a free-space check and at most two at a time. Vault: `40-invariants/inv-self-hosted-model-source-pinned-transport.md`.
