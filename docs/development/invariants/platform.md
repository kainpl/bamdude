# Invariants: Platform: requests, errors, runtime

Full text of the rules that [`CLAUDE.md`](../../../CLAUDE.md) keeps in short form, with the reasons and the history behind them. `Vault:` pointers name notes in the maintainer's private knowledge base; everything a contributor needs is here.

## Async-first

All I/O async. FastAPI `Depends()` for DI. Pair every `asyncio.create_task` with shutdown cancel. Autouse `_cancel_leaked_asyncio_tasks` drains pending tasks between tests. ⚠️ **Never call paho's `loop_stop()` on the event loop** — it joins the network thread with no timeout, and a thread parked in a TLS handshake against a printer that answers but never finishes it holds that join indefinitely (upstream #3068: the whole web UI stopped while the process stayed up). Let a paho client go through `utils/paho_teardown.py::retire_paho_client`, which detaches its callbacks inline, empties the client's outbox and runs DISCONNECT + `loop_stop` on a named daemon thread. ⚠️ The outbox goes FIRST: a client retired while its network thread sits in `reconnect()` has no socket, so `disconnect()` only sets a flag, the handshake finishes anyway and paho re-sends every unacknowledged command on that revived session — with `on_connect` detached nothing else empties it (a reconnect of the SAME client is covered by `_on_connect`, which drains before paho re-sends). `tests/unit/services/test_mqtt_reconnect_replay.py` drives a real paho client; a mocked one cannot pin that order. Vault: `40-invariants/inv-a-replaced-mqtt-client-is-closed.md`.

## The start-up heap is frozen once, first, and a running server never (spec process-gc-latency r2, 2026-10-29)

`core/process_gc.py` is the cyclic collector's ONE owner — `tests/unit/test_collector_has_one_owner.py` (an AST scan: aliases, `from gc import`, the module handed on) fails any other module that disables, enables, freezes, unfreezes, retunes or runs it. `main.lifespan` calls `prepare_startup_heap()` as its FIRST statement — before the farm guard, `init_db`, any connection or manager: one `gc.collect()` + `gc.freeze()` takes the ~0.8 M imported objects out of every later full collection (measured: ~400 ms → 30–70 ms on a server-like process), once per process — a second lifespan, a failed start or a restore never decide again, and the outcome is logged once. `BAMDUDE_GC_STARTUP_FREEZE=off` keeps the stock collector; a value other than on/off refuses the start. It skips, with one record and a stable reason, a host that switched the collector off or froze objects AFTER the import (`already_frozen` counts from the module's import — CPython 3.12 starts with a frozen set of its own), an interpreter outside the measured cells (CPython 3.12 with the GIL only — others `unverified_interpreter` / `free_threaded`), and a process already working (engine pool connections, printer clients: `late_start`). The suite runs with it off (conftest assigns `off`, not setdefault); the real start-up is proven in children that remove the variable and never import conftest (`integration/test_process_gc_startup.py`). ⚠️ A frozen object is never examined for cyclic garbage again: never freeze later, periodically or after a restore — an evicted import-time object in a cycle with runtime objects would keep them for the life of the process (the restore probe found none; the end-of-process unfreeze oracle is in the evidence). ⚠️ The support census (`gc.get_objects()`) walks only the unfrozen heap and reports `gc_frozen_objects` beside it. Vault: `40-invariants/inv-collector-startup-boundary.md`. Soft descriptor limits are adjusted by `core/process_resources.py` immediately after this heap boundary and before child processes; the helper never lowers soft or changes hard. Its FD diagnostics import dependencies before exhaustion, classify procfs link text without target filesystem access, and expose no paths.

## A request's transaction ends before its response is sent

`core/database.get_db` is deliberately NOT a yield dependency (upstream #3320): FastAPI keeps two exit stacks per request, and a yield dependency without `scope="function"` at EVERY call site is left only after the response went out — the commit ran behind a 200 the client already had, and a commit that failed was rolled back in silence. `get_db` enters `_request_session` (commit, shielded rollback and close) on FastAPI's function-scope stack through `enter_before_response`, so every route there is and every route to come gets the order with no call site to forget; without that stack it raises, never falls back. A commit that fails is the request's error (500), and commit time is part of response time. `tests/conftest.py` overrides `get_db` through the same `enter_before_response`, so the suite runs in production's order — an override written as a generator would hide it from every test (`test_get_db_commits_before_the_response.py` pins both). A new dependency that owns a transaction uses `enter_before_response` too; a session must not be used by a streaming body or a background task after the handler returned. Vault: `40-invariants/inv-request-transaction-ends-before-the-response.md`.

## A null in an update body is "not sent" or a refusal — never a write into a NOT NULL column

A PATCH/PUT body that writes one row and has a field accepting null either inherits `schemas/not_null.IgnoresNullForRequiredColumns` and names its table (`__orm_table__`: a null for a column that cannot be empty is dropped before validation, a null for a nullable column still clears it; `__keeps_null__` names a field whose null the schema refuses itself), or refuses the null itself with a 422 and is listed with its reason in `tests/unit/test_not_null_update_schemas.py`, which walks every route. Routes that apply `model_dump(exclude_unset=True)` + `setattr` answered 500 otherwise. Never put the base on a schema whose validators already answer 422 for a null (the Workshop, drying schedules, customers, cameras): it would turn the refusal into a silent "unchanged". Vault: `40-invariants/inv-update-null-is-unchanged-or-refused.md`.

## API refusals are translated at the boundary, never at the raise site

A route refuses with an English sentence (`HTTPException(409, detail="…")`) and knows nothing about language; one handler (`backend/app/i18n/api_errors.py`, installed right after `app = FastAPI(...)`) looks the sentence up in `data/api_errors_uk.json` — the English sentence IS the key, f-strings are `{}` templates matched by regex — and answers in the **system** language (`current_language()`, never `Accept-Language`). Never translated: `MACHINE_READ` (the 401 texts `api/client.ts` branches on), bare codes like `parts_not_editable` (`is_code`), and `str(e)` of foreign exceptions. Anything the frontend must *react* to travels as `{"error": code, "message": …}` (only `message` is translated; e.g. `not_sliced`); **never branch on `ApiError.message` text**. Hand-built refusals go through `json_error(status, detail)`, not a bare `JSONResponse`. Coverage is a test: `scripts/api_error_catalog.py sync` + `tests/unit/test_api_error_details_have_ukrainian.py` (AST scan; missing sentence, stale key or placeholder mismatch fails CI). Vault: `40-invariants/inv-api-refusals-translated-at-the-boundary.md`.

## Case folding is Unicode-aware on every backend, decided in `core/case_folding.py` — never in a route

SQLite's built-in `lower()` folds ASCII only, and SQLAlchemy compiles `ilike` to `lower(col) LIKE lower(:q)` there, so `?q=ЛАМПА` never found «лампа»: every SQLite connection (`configure_sqlite_connection`, also attached by `tests/conftest.py`) shadows `lower`/`upper` with Python's. A PostgreSQL database created with `LC_CTYPE=C` folds ASCII only too (measured on the dev server): `init_db` probes once per boot, `reinitialize_database` again after a restore (`probe_postgres_case_folding` — `SELECT lower('Ж') = 'ж'`, then each candidate of `FOLD_COLLATIONS` is verified before it is trusted), and when the database cannot fold, the folding compiler (`case_folding.compiler_for` — the mixin laid over whatever statement compiler the driver's dialect carries, never assigned over it) renders `ilike`/`lower`/`upper` through `pg_c_utf8` (17+) or `und-x-icu`, and `routes/archives.py::_use_fts_search` takes the `ilike` branch only when a collation was chosen; with none, FTS stays on — neither the m001 tsvector nor `ilike` folds and the index is faster; a server with neither collation logs the cure (recreate the database with a UTF-8 locale). The FTS statement runs inside a SAVEPOINT (`db.begin_nested()`, never `db.rollback()`, and `matched_ids` is assigned only after the block exits) — a refused index query, and the search term is the user's, would otherwise abort the transaction and take the `ilike` fallback down with it. A folded lookup that finds several case-variant users — an install could hold `Ірина` and `ІРИНА` before the fold was Unicode — picks the exact-case match, else the oldest, and warns once (`core/auth.py::_pick_folded_match`); the duplicate checks read the first folded match and refuse as they always did (400 on user create/rename, 409 on LDAP provisioning), never 500. The bundled server (`--builtin-locale=C.UTF-8`) and the official Docker image fold natively and compile exactly as before. Uniqueness keys (`name_key`) are computed in Python and never depended on this. Vault: `40-invariants/inv-unicode-case-folding.md`.

## i18n

Never hardcode user-facing strings. Frontend `useTranslation()`. Backend `t(lang, ns, "key.path")` + `escape_md()` for MarkdownV2. **en + uk only** — keys in BOTH.

## Local microservices report their work through the parent log

The parent runtime that owns a child process/RPC logs service readiness, loss and restart, then wraps each meaningful operation with a start and terminal outcome (success, failure, timeout or cancellation), elapsed time, a correlation ID and a safe result summary or sanitized failure reason. A child's stdout/stderr may only reach a bounded diagnostic buffer; an HTTP 200, queued task or `health=ready` is not proof of completed work. Aggregate hot paths such as camera frames, scan pages and polling instead of logging every event; never log credentials, raw payloads or sensitive paths. Verify success and failure visibility in the parent logger with a real worker test. Vault: `40-invariants/inv-local-microservice-parent-log.md`.

## CSP + security headers

`security_headers_middleware` registered AFTER `auth_middleware` so it wraps 401/503. `script-src 'self'`; `connect-src 'self' ws: wss:`; `frame-src 'self' http: https:` (Spoolman and external links are embedded, also over plain http on a LAN); `frame-ancestors 'none'`. HSTS on HTTPS. `/sw-register.js` served by `serve_sw_register()` so strict `script-src 'self'` holds.
