**Adaptations / divergences:**

1. **#2527 WS-payload gap (upstream bug we had to close).** Upstream wired `exists` only into the REST `PrinterStatus`. Our WS `printer_status` payload merges wholesale into the `printerStatus` TanStack cache (`{...old, ...statusData}` — the `ams` array is replaced, not merged), so an `ams` array without `exists` would drop the flag on the very next push and the fix would last one render. `exists` therefore also emitted from `printer_state_to_dict`.
2. **#2582 `cali_idx` secondary signal.** Upstream reads `matching_kp.cali_idx` at the assign call site. Our path delegates the `extrusion_cali_sel` push to `calibration_service.apply_active_calibration_to_slot`, which re-resolves the **live** `cali_idx` (stored one is a hint only), so the caller can't know it. Added `BambuMQTTClient.note_assignment_cali_idx(ams_id, tray_id, cali_idx)`, called by the calibration helper right after it fires — keeps the "loaded but K-profile not applied" case working without changing that helper's `(fired, cache_row)` return signature (8 call sites + 4 tests).
3. **#2604 realignment block skipped.** Upstream's `configure_ams_slot` also realigns `effective_tray_info_idx` to `kprofile_filament_id` — added upstream **before** this cycle (`b30a2831`, pre-0.2.4.9) and deliberately not in our tree. Only the `setting_id` back-fill (the in-range change) was ported.
4. **#1899 guard placement.** Upstream guards inside its flat `_start_print` before preheat/upload. Ours sits in `print_scheduler._start_print` right after the file-exists check and **before** the `pending→printing` CAS — nothing to unwind on a block — using our `_fail_item` (which also resets the per-printer queue counters upstream doesn't have) + `on_queue_job_failed`. Library-file dispatch is a no-op either way (`LibraryFile` carries no nozzle diameter).
5. **A2L `ams_load` range check.** Upstream widened an explicit `tray_id in range(16) or (254,255)` 400-gate to accept 24-27. We never had that gate, so 24-27 already passed — only the `Query` description was updated.
6. **`ams_filament_setting` patched at TWO sites.** Our `reset_ams_slot` shares the same branch shape as `ams_set_filament_setting` (both emit `ams_filament_setting`); both got the A2L branch.
