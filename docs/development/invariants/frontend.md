# Invariants: Frontend

Full text of the rules that [`CLAUDE.md`](../../../CLAUDE.md) keeps in short form, with the reasons and the history behind them. `Vault:` pointers name notes in the maintainer's private knowledge base; everything a contributor needs is here.

## Modals close only by their buttons or Esc — never on a click outside

Every modal renders through `components/Modal.tsx` (portal into `body`, z-index = 50 + its position in the modal stack — never hand-written, backdrop without a click handler, header X, `role="dialog"` + focus); `components/modalStack.ts` owns the ONE Escape listener (on `window`, not `document` — 12 tests dispatch there) and gives Esc to the topmost modal only, so a `ConfirmModal` over `PrintModal` closes alone. `modalStack` also owns every `inert` attribute of the modal layers — the focus trap: while the stack is non-empty `#root` is inert, and so is every overlay except the topmost, written imperatively in `register`/`unregister` (never a React prop), so the layer below is live again in the same cleanup pass in which `useDialogFocus` returns focus to it; `Modal.tsx` calls `useModalStackEntry` BEFORE `useDialogFocus` for exactly that reason (cleanups run in declaration order — `Modal.test.tsx` pins it). The hook reads the opener in a layout effect and returns focus in the passive cleanup — before the stack's passive effect can make `#root` inert, and after its cleanup has made it live again. Two modals unmounting in one commit clean up top-down, so the outer return is deferred by a microtask when the opener is still inside an inert subtree. Toasts are portalled into `body` because a viewport inside `#root` would be dead under a modal. A non-modal overlay inside `#root` stays BELOW the modal layer (`z-[49]` at most — `modalShellOwnership.test.ts` fails a `fixed` element at z ≥ 50 in a file that does not portal); at or above it the overlay is visible-but-dead under a modal. The menus that open dialogs from their items (CardActionMenu, TrashSplitButton, the file-manager menus) give focus back to their trigger on every close, so the dialog has a live element to return focus to; a popover that never opens a dialog does not need to. The stack is mount order with one correction carried by `ModalAncestryContext`: an ancestor that registers after its descendant (same-commit mount — React runs child effects first and lands portal children in `body` child-first) slides in just below it; nesting depth is deliberately NOT the order, because an app-level alert raised over a nested chain must sit on top of the chain. `variant="lightbox"` is the single sanctioned click-outside (a picture on a dark ground); a menu/popover/drawer/loading/viewer overlay that must dismiss on outside click says so with `// not-a-modal: <kind>` on the line above its tag. An Escape handler for an INNER layer (inline edit, dropdown) lives on `document` and stops propagation; page-level shortcut handlers check `isAnyModalOpen()` (Layout, KProfilesView, ArchivesPage) — `stopPropagation` cannot reach a sibling `window` listener. `__tests__/components/modalShellOwnership.test.ts` scans the sources and fails on any other full-screen overlay (any `bg-*` ground counts — the fullscreen camera is `bg-bambu-dark-secondary`) — a new modal that draws its own `fixed inset-0` is a red CI, not a style choice. `size` is a closed table (`xs…8xl`, `full`; `full` has no `max-h` cap); `8xl` exists only because `index.css` declares `--container-8xl`; computed geometry goes through `panelStyle` (inline beats every class — overriding the panel's base classes via `panelClassName` depends on Tailwind's emit order). `Layout` also swallows `dragover`/`drop` for `Files` drags app-wide: the old full-screen overlays were the only thing stopping a dropped file from navigating the browser away. Vault: `40-invariants/inv-modals-close-only-by-buttons-or-esc.md`.

## `<main>` is no scroll box; a page-level `sticky` sits below the header through `--app-top`

The window scrolls the page: an `overflow` on `<main>` (which never scrolls itself) makes it every sticky's scrolling ancestor and no sticky holds (`Layout.test.tsx`). So a page's sticky bar sticks to the window, under the fixed compact header (`h-14`, below 1144 px): `Layout` sets the header's height once as `--app-top` on `<html>`, every page-level sticky offsets by it (`top-(--app-top)`, `top-[calc(var(--app-top)+…)]`), and `index.css` makes it the document's `scroll-padding-top`, so `scrollIntoView` and keyboard focus stop below the header. `__tests__/components/stickyBelowHeader.test.ts` fails on a page-level `sticky` with any other `top-*`; a sticky inside a scroll box of its own keeps `top-0` and is listed there with its box. Vault: `40-invariants/inv-main-is-no-scroll-box.md`.

## The bundle parses on Safari 16.0 (owner, 2026-09-26, audit D12)

Nothing that reaches `static/assets/*.js` may use a **regex lookbehind** or a **class static block** — both arrived in Safari 16.4. A regex literal is validated when the MODULE compiles, so one in an entry chunk is a white screen on iOS 16.0–16.3 with no error and every other platform fine; esbuild lowers syntax to `build.target` but never rewrites a regex, so no target setting helps. `npm run build` ends in `check:baseline` (`frontend/scripts/check-browser-baseline.mjs`), which fails the build on either; `src/__tests__/utils/safari16Baseline.test.ts` scans our sources for a lookbehind or a `remark-gfm` import — a text scan, so describe a pattern in words, never quote it in a comment. `remark-gfm` is gone (its autolink-literal extension carries a lookbehind): the README panel's GFM is assembled in `utils/remarkGfmNoAutolink.ts`, and bare URLs no longer auto-link. `GcodeEditor`'s number rule is `wrapStandaloneNumbers`, which retries a refused candidate from the next position exactly as the regex engine did. Raising the floor is a product decision: drop the entry from the script's `FORBIDDEN`, never the check. Vault: `40-invariants/inv-bundle-parses-on-safari-16.md`.
