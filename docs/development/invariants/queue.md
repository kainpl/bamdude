# Invariants: Queue and dispatch

Full text of the rules that [`CLAUDE.md`](../../../CLAUDE.md) keeps in short form, with the reasons and the history behind them. `Vault:` pointers name notes in the maintainer's private knowledge base; everything a contributor needs is here.

## Single dispatch layer

Only `background_dispatch` runs prints. `print_scheduler._start_print` is a thin wrapper. Dispatcher creates exactly one archive per physical print, wires `PrintQueueItem.archive_id` in same txn, signals via `PrintDispatchJob.completion_event`. External prints (printer screen / Send-to-Printer) create their archive in `on_print_start`, at print start — see *The archive row is created at PRINT START* below.

## Dispatch is claimed per PRINTER, not per item

`set_queue_busy()` flips `PrinterQueue.status='printing'` and `print_scheduler` seeds `busy_printers` from it; `_dispatch_holds` adds an in-memory post-dispatch window. ⚠️ **Every print now also holds a queue ROW while it runs** — direct prints take it at dispatch (`queue_batch.claim_printer_for_direct_print`, `status='printing'`, `position=0`), external ones at print start (`mark_queue_printing_for_printer`); the dispatcher owns the release. Before that, a "print now" claimed nothing until the printer had already started, so the queue saw an idle printer for the whole upload and dispatched over the job (0.5.4). "Queue item" therefore no longer means "work somebody queued". Upstream's per-item `dispatching_at` is deliberately NOT ported — it would be a second, weaker source of truth. **This DB claim is what serialises tier 1**: `on_print_complete` runs the swap macro *inside itself* and only then calls `set_queue_idle`, so the printer stays claimed across the whole plate change whatever the live MQTT says. The swap wrapper moves `stg_cur`, completion keys off `gcode_state` — different fields, so a macro can never be mistaken for a print ending.

## The lane comes first, and the claim dispatches the row its pass planned from (G03 B1, 2026-11-20)

A queue's lane is its process lock + SQLite's writer / the PostgreSQL advisory xact lock (`queue_ops.claim_lanes` / `queue_claim_scope` / `lane_session`; `held_lanes(db)` says which a session holds; `queue_scope_lock` — the append/reorder lane — takes no process lock on SQLite but takes SQLite's writer (`take_write_lock` on its header) before its body reads: pysqlite opens a transaction only at the first write). A transaction that holds a queue's job row and then any other lock, or writes job rows and their header, takes that queue's lane before its first row lock — all its lanes at once, ascending — or ends before asking for another; only one-row statements and header-only transactions stay lane-less, and only a lane holder changes which row is next (`/start` included). A job row read before the lane is locked by its id AND the queue it was read in, in the SQL before `FOR …` (`lock_named_rows`, `lock_judged_row`, the edit's apply): a row that moved meanwhile is never locked — its lane is someone else's — and its absence is the refusal. A row of another queue that must be refused (a foreign `printing` claim) is read without a lock. The writer guard checks the queue constraint in the predicates of the SELECT that takes the row lock (`unaddressed_job_locks`). A conditional predicate constrains the queue in every branch. Under the lane the claim re-reads its row and refuses `item_changed` when anything but the waiting diagnostics differs from the pass's load (`queue_row_basis`); a verdict of the pass (gate skip, source failure, timelapse pause) is written only under the claim's own admission; an edit validates outside and applies under its lanes (409 `queue_item_changed`), its target's header and printer read once before its checks and held for them (`checked_facts`: the model check, the swap decision, the routing intent and the rack pick take the rows from that snapshot) and compared again under the lanes — a target deleted or replaced meanwhile is refused. In-place edits refuse a queue already missing from the snapshot before swap and routing checks (single/batch conflict, bulk skip). A halt never overwrites another run's claim — `halt_lane`: `error` on its own header, `is_paused` beside another run's, a stale `printing` header only by a CAS with no printing row (`stale_only`); a header is released only by an address (`set_queue_idle(expected_item_id=…)` or the stale form). Several AutoQueue rows are locked ascending (`lock_auto_rows`); the AutoQueue pass commits each placement on its own and writes router rows only by their view (`write_router_rows`). A writer whose rows an archive, an order or a batch names reads its lane footprint first and refuses when it grew (409 `queue_selection_changed`). A row enters a queue only under the header it was validated against (`queue_header_holds`, by `recovery_identity`; an AutoQueue placement compares the non-NULL incarnation its eligibility read with the printer, `EligiblePrinter.queue_identity`); printer deletion's final step (the printer, its queues, jobs and maintenance rows) is one transaction under that lane; archives deleted with it are committed one by one before it. A foreign-key check is a lock: explicit locks of header, job and AutoQueue rows are `FOR NO KEY UPDATE`, a parent is taken before any row its holders wait for, and the attach takes every row lock before the file-path lock. Every function that writes or locks a `print_queue` / `printer_queues` / `auto_queue_items` row is in `tests/queue_writers/`'s allowlist with its lock class — a new writer is a red build. Vault: `40-invariants/inv-queue-lane-first.md`, `40-invariants/inv-fk-check-is-a-lock.md`.

## "Only after a successful previous print" has one reader, and a success releases it by itself (G03, 2026-11-19)

`services/previous_print_gate.py` alone answers the `require_previous_success` question for both tiers and the rebalancer (`PrintScheduler.previous_print_succeeded` delegates; `print_queue._acknowledge_blocking_failure` too). The newest finished row is `completed_at DESC NULLS LAST, id DESC` — a bare `DESC` put a cancel without an end time first on PostgreSQL and hid every later failure. Successful rows are DELETED (completion clean-up, Clear plate) while failed ones stay, so every writer that finishes a row as `completed` (live completion, reconciliation close, structural recoveries) marks the queue's older unacknowledged failures `gate_acknowledged` in its own transaction (`acknowledge_failures_before_success`) — without it one old failure kept the gate shut for ever. An attempt that published no start is written `gate_acknowledged` (an unknown send still gates); a published start the printer did not run gates. `check_queue` judges the gate only for each printer's next row (a later row no longer gets `skipped` while its head waits). `POST /queues/{id}/acknowledge-failure` releases AutoQueue work waiting on `previous_print_failed`; the queue response carries `previous_print_failed`. Vault: `40-invariants/inv-previous-print-gate-one-reader.md`.

## A batch action acts in one queue (G03, 2026-11-19)

AutoQueue promotion copies a router row's `batch_id` onto rows of DIFFERENT printer queues, so every `/queue/batch/{batch_id}/…` route takes `?queue_id=` and touches only that queue's rows; without it, a batch whose active rows span queues is 409 `batch_spans_queues` — never a farm-wide action by accident. Counters are recounted for every queue a write changed; a batch move is checked like a single move (model, target swap rule), whole or not at all. An API key's printer scope on a batch route is checked against the named queue's rows.

## Routing is NOT dispatching (auto-queue)

`find_eligible_printer` must never gate on *readiness* — plate-clear gate, drying, stagger are `check_queue`'s questions, asked again at dispatch. Readiness only **ranks** candidates there (ready wins, busy still gets work). Gating at routing time doesn't make anything safer: the item just waits in the printer's queue visibly instead. It DID make an idle farm report `Busy: …` with an empty per-printer queue and therefore no Clear Plate prompt — that prompt renders off the queue auto-queue was refusing to fill. Keep the busy set (an active claim or a pending row that is due and unstaged) and the filament/colour match. The shared predicate in `printer_occupancy` also selects the scheduler's runnable head. A future or staged row lowers the printer's rank after readiness, model and colour (the whole rank is written once — «The printer order of a placement has one reader» below), and only the runnable head can pause a queue over timelapse space. Each automatic placement is due and unstaged, so it holds the printer for the next tick. The claim's head query fixes the ordering at its recorded `started_at`. A halted printer queue (`is_paused`, or `status` `error` / `paused` until Resume) is a FILTER too, not a rank term (owner, G03 2026-11-19): it refuses all work, the category `is_paused` already belongs to, and as a rank it still won when it was the only fit — the job then lay in a stopped queue instead of waiting in AutoQueue for any printer. `printers_for_item` filters it with the waiting code `queue_halted` naming the printer, `require_auto_placement` refuses it, and the rebalancer's forecast gives a halted lane no new placements.

## The printer order of a placement has one reader (C01, upstream #3480 / #2915)

When several printers can take an AutoQueue job equally well, the operator's order decides which one gets it: `model_dispatch_order` — `fewest_hours` (the default), `most_hours`, `least_recently_used`, `priority` (any other stored value reads as the default). `services/printer_pick_order.py` is its only reader for routing: `read_pick_order` reads the setting and, for every `is_active AND NOT archived` printer (no queue, auto-distribute or connection filter — the switched-off printers the wake step orders need facts too), the hours (`runtime_seconds / 3600 + print_hours_offset`, the maintenance counter), the priority (`printers.dispatch_priority`, m271, lowest first, NULL last) and, under `least_recently_used` only, the last finish — the newest `completed_at` of the printer's archives that are prints, one row per printer read down `ix_print_archives_printer_completed` (m271), never a grouped maximum over the whole archive: a dispatch error (`not_dispatch_failure`), an aborted attempt (`dispatched_archive_filter`) and a filed-only row (`status == "archived"`) printed nothing; a finished print in the trash still counts, as upstream's print-log run outlives its archive. `pick_key` turns them into a key, larger first; a printer without facts keys `()`, which sorts below every key — it ranks after every printer with facts, never "neutral".

The rank is ONE tuple, `printer_occupancy.placement_rank`: `(ready, exact model, colour matches, no deferred rows, the order's key, the remaining-filament level, -printer_id)`. The order decides after readiness, model, colours and deferred rows — they say whether the job can start soon, which the order is not about — and **before** the remaining level (owner D3, 2026-11-28): between equally fit printers the chosen order wins; `prefer_lowest_filament` then picks the trays inside the printer and separates only printers with an equal place in the order. Every chooser ranks with it: `find_eligible_printer` (the AutoQueue pass reads the order once and hands it to every call, the plain-printer probe included; assign-now reads it when more than one candidate is left), `offline_candidates_for` (the wake step: exact model first, then the order, then the id), `queue_rebalance._receivers` and `rebalance_replay.replay`. A second reader of the setting or of a printer's priority would let one of them pick differently, and the rebalancer would forecast a router that does not exist.

The replay advances what the router will read later: at every simulated print end with a known duration a lane's hours grow by its PRINTING time — never the preparation before it, never the plate service after it, because the printer's counter grows only while it reports RUNNING — and its last finish becomes that end. A print being dispatched keeps its preparation folded into `Held.seconds` (a started run's `prep` counts as done) and carries its printing time in `Held.print_seconds`. Unknown durations change nothing: the lane is frozen and every job it could reach ends unknown. The priority never moves. Guard: `test_printer_pick_order_has_one_reader.py`; T-A25 (`test_rebalance_tail.py`) holds under `most_hours`, `priority` and `least_recently_used`. Vault: `40-invariants/inv-printer-pick-order-one-reader.md`, `60-specs/upstream-c01-printer-pick-order-spec.md`.

## Rebalancing moves only PENDING line work, and a move is all-or-nothing (spec 2026-09-10)

`services/queue_rebalance.py` may convert an auto-queue row in place and create its `k−1` companions — never a per-printer row, never an assigned / scheduled / staged / pinned / located / archive-sourced / un-filed one (`refusal`; the closed `SKIP_REASONS` list is mirrored by `autoQueue.rebalance.skipped.*` in both locales). The target plate and the receiving model's profile are read BEFORE the first write, and the move is ONE captured revision and ONE transaction of rows (spec rebalance-companion-atomicity B1, 2026-10-29): the companions name the blob the move captured and published, assembled by the public add's own builder (`auto_queue_add.build_auto_queue_rows`, which reads only the database it is handed — no file, no capture, no publication, no commit), and the conversion, every companion and every stamp are written in a SAVEPOINT under the pin and committed once (`_write_group`) — another reader sees the old job or the whole group. A failure before the commit rolls the savepoint back (`creation_failed`; nothing durable, the automatic move not spent, the row refreshed for the caller); a commit whose outcome is unknown stops the pass and is never undone by a delete (a committed group is stamped, so no automatic pass repeats it). Positions are `max(pending) + 1…` read in that transaction without the storage guard — a concurrent add on PostgreSQL may take the same one, and the router's id tie-break orders them. "Ready" — the tick's busy set via `auto_queue_eligibility.busy_printer_ids`, AND `_is_printer_idle(pid, require_plate_clear=True)`, AND not in the tick's Home Assistant interlock set (handed in; a manual door reads it once), AND a queue `check_queue` will actually dispatch from — status not `paused`/`error`; an offline printer is out whole — is asked only to pick who RECEIVES moved work and whether a home printer would take the job now, which keeps *Routing is NOT dispatching* intact on both sides — the router is never gated, and work never moves to a printer that only looks free. ⚠️ **Every printer is asked about the JOB, never its model** (spec rebalance-job-feasibility r2, 2026-10-28): `queue_rebalance._FitOracle` runs the shared `resolve_filament_routing` under the job's own `auto_policy` over its ACCEPTED source (read once per distinct source per pass) — busy homes included, because the router checks busy before it resolves and its facts never cover a busy printer — never `find_eligible_printer`, which writes onto the row; verdicts are cached per pass by requirements, `RoutingPolicy.fingerprint`, printer, `feed_signature`, exactness and `prefer_lowest`, and `require_previous_success` stays outside the cache. An unread ready home holds the job for a pass (`eligibility_unknown`). ⚠️ **Both finishes come from ONE forecast of the router's whole tail** (spec rebalance-tail-time r2, 2026-10-28; `services/rebalance_replay.py`, pure): every row the router sees (`auto_queue_eligibility.router_view_conditions` / `router_order`, shared with `_fetch_pending`, the id last) dealt out over the router's own population (`_router_population`, online) in its order and rank — its SQL keys exactly (Codex r1 T-R2: `Job.order_seconds` is the stored estimate, so a 0 sorts first although it dates nothing; `null_group_first` sorts a NULL model as the dialect does, first on SQLite, last on PostgreSQL) — the order a wave was sorted in holds for that wave, a `been_jumped` mark (`jumps` = `_mark_jumped_peers`) counts from the next — with farm_forecast's preparation, plate service, operator hours and staggered starts. Every job is placed and prepared as `_assign` writes it (Codex r1 T-R1/T-R3): `auto_queue_scheduler.compose_options` (the creator's saved profile for the printer's model, then the order's entry for the job's model) is the one composition both read, `_Assignments` asks it once per (creator, order choices, model, source fact) and printer, and a printer it would refuse — options → `incompatible_target`, the swap rule → its reason — is no fit for that job; a job's preparation is its order's entry for its own model (the saved profile carries none — pinned by a test); a target's converted row keeps its creator, its companions are judged by the mover, each on its own pool. A lane is free now exactly when the router may place on it now (the T-A25 test compares the first wave with a real tick); a print being dispatched (claim, no archive yet) is its estimate plus preparation (`_dispatching`), one past its estimate is over (`OVERDUE_SECONDS`); what has no forecast release is unknown, never 0 — no estimate (a 0 s one included), an HA hold, busy with nothing to date — and taints its start group only while something can still start there; an unknown home or trial is `forecast_incomplete`. A queue that starts nothing (paused/error status — `Lane.stuck`; a row its order forbids there — `Held.blocked`) never frees: the job placed there has no home finish (as the previous package's exclusion), it is never a receiver, and it makes nothing else uncertain. A home vetoes (`home_model_idle`) only when the first wave hands the job to a ready printer with a known start. The trial converts the row in place and files `k − 1` companions after EVERY pending row (`max_position`); the moved rows land only on the pool of ready, dispatchable, free fit receivers, each spent once per pass; a plate whose bound `ceil(k / c) · t` from now already ends after the home is proven slower untried — never the target's baseline clock, removing the original can free a stagger window — and a trial stops once its prints started or can no longer start in time; it replays only the baseline's parts it touches (`components`: fits, stagger groups, SJF groups). One budget per pass (`REBALANCE_WORK_BUDGET`, measured, → `forecast_budget`; a move whose own replay ran out stands, everything after it waits); the decision runs in a worker thread over plain data (`_Forecast`, `_decide`), and the cyclic collector stays the process's: a pause around the decision only moved a full collection from the worker onto the loop and never made one rarer (Codex r1 T-R4, measured against the router on the same stands), so nothing in the rebalancer switches it — the collector's one owner is `core/process_gc.py` (see *The start-up heap is frozen once* below). The tick moves a row ONCE (T23, owner's decision): `rebalanced_at` or `rebalanced_from_model` → `already_rebalanced_auto`, the row stays in the tail; only the buttons move it again. A move that does not apply ends the pass's plan (`plan_invalidated_after_apply_failure`). `_still_holds` re-reads, after the target copy, the row, the copy's revision of the target file (the library row's path + the original's size and `st_mtime_ns` from the capture receipt, against the `SourceIdentity` the decision read), the line's catalog (the target plate's recipe and the job's own yield — `k`, finish and moved parts) and the copy's family enrichment — both in a session of its own, because the pass's session never expires on commit and a SELECT hands back the rows it already holds as they were (Codex review r2; the target's library row is read with `populate_existing` for the same reason, never `expire_all`) — and every receiver — queue, busy set, feed, idleness, its model from its row and the «compatible models» setting, and the router's assignment rule over fresh inputs: its swap mode, the owners' saved profiles (a session of its own) and the declaration the COPY carries, confirmed by the captured bytes' hash, for the converted row's creator and the companions' mover alike (`_assignment_changed` → `assignment_refusal`, the one function the decision asks too; the row's identity carries its order choices and creator — Codex review r2, T2-R1) (`eligibility_changed`, no cooldown). ⚠️ That is evidence, not ownership: two runs can both pass it, so `_claim_row` reads the row once more UNDER ITS LOCK — after the order's lock, as the router's claim does; `take_write_lock` on SQLite, `FOR UPDATE` on PostgreSQL — right before the write, and converts only the row the decision read (Codex review r1: a second conversion added another k − 1 companions). The tick hook runs after the placement pass has committed, behind `auto_queue_rebalance_models` (default off) with a per-line cooldown; both manual routes force. The replay ranks free lanes as the router does, the printer order included, and advances each lane's hours and last finish at every known print end (C01, above). ## A job that has been sent but not started is not an orphan

`print_reconciliation` re-arms on every MQTT client recreation (#1542) and the dispatcher itself triggers reconnects via `ensure_fresh_connection_for_printer` — so the sweep lands mid-dispatch routinely. Guard on `PrintArchive.created_at` (`_JUST_DISPATCHED_SECONDS`), **not** on `_dispatch_holds`: the hold is registered only after a *successful* dispatch, which is seconds too late. Symptom when broken: queue item marked completed before its own archive starts, its row and its `auto_queue_items` partner left behind (auto-clean lives in `on_print_complete`, which never ran).

## The dispatch guard asks the plan, not the feed (2026-09-30)

Between the dispatcher's preflight and publish one question is asked — `filament_preflight.plan_holds`, by `settle_plan`, `final_guard` and the synchronous `DispatchRoutingGuard.validate` — and only of the slots the plan CHOSE, through the resolver's own `filament_routing.source_fits` (plus `feed_preconditions` / `channel_refusal`): a spool swapped in a slot the job does not use, a new tag on the same filament or a remain update is not a changed plan; `unknown` waits, never passes. A hotend re-fitted on a nozzle the plan prints from is a changed plan (`DispatchRoutingGuard.nozzle_diameters`, recorded at preflight). The runner reads the MQTT session before sending the K bind; `_rebind_if_moved` re-sends it when the session moved and returns the session it reached; `final_guard(bind_generation=…)` refuses any other session (`printer_reconnected`), and `validate` holds the publish to the session the final check confirmed. `validate` never reads a file (`left_tpu_check` precomputed, `with_model=False`). One bounded wait (`settle_plan`, `FEED_SETTLE_TIMEOUT` / `FEED_SETTLE_CONVERGE`) covers a new session, an operator mid-swap and our own slot writes; the pre-start K bind is re-sent when the session changed or its own keys moved (`_rebind_if_moved`). The mapping never changes after preflight — a refused start is a new plan next tick. `runtime.blocked_revision` latches only `LATCHING_REASONS` (`feed_settle_timeout`): a refusal because the feed moved never parks a row. A pinned slot that is EMPTY prints from its AMS Backup twin — the firmware's `filam_bak` group, remembered per slot while loaded by `services/backup_group_memory.py` — and the twin's id is what is sent and recorded on the row (`_record_dispatched_mapping`); never for a row without a routing intent. Vault: `40-invariants/inv-dispatch-guard-asks-the-plan.md`.

## A direct rack (H3C, P3C) is routed by Bambu Studio's candidate rule (N01 stage B, 2026-11-28)

On a direct-connected rack the tray decides the PrintTool, so routing does not pick a nozzle — it picks trays whose hotend has the spec the filament was sliced for (`nozzle_diameter` / `volume_type` of `<filament>` in `slice_info`, read only for a `handle_hotend_as_extruder` slice; "Hybrid" or none — any flow). Per existing hotend the candidates are its one bound tray (`direct_rack.bound_slot`) plus every tray of its `bind_ams` sub-AMS (AMS, AMS 2 Pro, AMS-HT); `printer_feed_snapshot` stamps each source with that hotend (`rack_addr`) and Studio's `QuerySlotFeedBlock` (`feed_block`). An automatic plan takes no blocked tray — an unloaded AMS 3P slot or external input (manual feed), any other tray while an external or rack-AMS filament is at the hotend's inlet; a pin may take one, and the plan carries a notice (`manual_feed`, `shared_print_tool` when two sources that cannot both retract share a PrintTool — the owner's decision, as Studio: send with the warning). Pins keep the `nozzles` 0/1 format (every channel is on extruder 0); `planned_nozzle_diameters` is keyed by the hotend's dock instead, and the rack's facts are in the snapshot revision, so a swapped hotend is a changed plan before the upload. Two filaments may share one tray (Studio's mapping is not injective there). Studio's blocking statuses refuse first (`rack_preconditions`): a dynamic nozzle-map slice, a moving rack (waits), no hotend, a detached tool, no dock docking-calibrated (only once `holder.info2` was seen — Studio has no direct rack without it). A calibration row is exempt from routing, so it asks its tray's hotend at `start_calibration` and again in `preflight_item`'s exempt branch, where an old row m275 marked waits (`rack_mapping_recreate`).

## Staggered start is capped per GROUP, and an unassigned printer is a wildcard (m164)

A printer's stagger groups come from `services/stagger_groups.py` — its picked tags × the nearest picked location ancestor; the key is `(tag_id | None, location_id | None)` and both axes off is today's one bucket. **A printer with no picked tag (or no picked ancestor) is in EVERY group and starts only when all have room** — its phase is unknown, so it may be on any; this is also why enabling a split before tagging changes nothing. Slots never store groups: the resolver is loaded once per tick and re-asked, so a tag pinned mid-heat counts next tick. A printer never blocks itself (its own slot is excluded). **Strict mode for direct dispatch = refuse instead of wait**, decided in `background_dispatch._process_job` BEFORE the acquire, through the runner's four failure exits, leaving the queue idle; queue jobs are never refused. Tags are an entity (`printer_tags` + `printer_tag_links`, links written only by `services/printer_tag_service.py`; SQLite ignores the cascades); a tag or location that is a group returns 409 on delete. ⚠️ The model-import list lives ONCE, in `core/database.py::import_all_models`, shared by `init_db` and `tests/conftest.py::test_engine` (the copy conftest used to keep drifted) — a model missing there is invisible to the app AND to every test; `tests/unit/test_every_model_module_is_registered.py` compares it against the directory. Vault: `20-systems/staggered-start.md`, `40-invariants/inv-stagger-unassigned-is-wildcard.md`, `20-systems/printer-tags.md`.

## A printer's queue is the `printer_queues` row with the printer's own id — always

`PrinterQueue.id == printer_id` is an invariant the scheduler leans on everywhere (`item.queue_id` is read as the printer id), and `services/printer_queues.py::ensure_printer_queue` is the ONLY creator: it looks the row up by id first; an orphan of a deleted printer sitting on that id is adopted (stale items dropped), a live printer's queue misplaced under another id is re-keyed home (items + archives follow), and the startup sweep runs this for every printer. **Never create a `PrinterQueue` under "the next free id"** — d93977c8 did, and the user killed it the same day (2026-09-05). Vault: `40-invariants/inv-printer-queue-id-equals-printer-id.md`.

## A queued job owns its bytes, and the spool is one writer (m173)

After capture, nothing on the print path reads the library file, the archive or the share again — it reads the job's snapshot. `queue_sources` holds **one row per distinct content, never per job**: the key is the SHA-256 of the bytes that were actually captured (`UNIQUE` + a named `length(sha256) = 64` CHECK), the file lives at `DATA_DIR/queue-spool/objects/<aa>/<sha256>.<ext>`, and a half-written capture sits in `queue-spool/staging/<token>.part` with **no row at all** — so "being prepared" is not a state the table can be in. Both tiers carry `queue_source_id` + `source_snapshot`; `services/filament_intake.py::item_descriptor` is the readers' single choke point and every consumer goes through it (dispatch, the scheduler, preflight, the patcher, the archive pipeline) — never a fifth path of its own. A job whose `library_file_id` and `archive_id` are both NULL is a first-class job: anything that treats missing original refs as "not dispatchable" is a bug. ⚠️ **`services/queue_sources.py` is the ONE writer** — capture runs on a bounded daemon-thread worker off the event loop, publish is atomic under a single `storage_mutation()` guard, and a `CaptureReceipt` is spent exactly once (a revived receipt whose staging file has already moved is what the pessimistic install exists to make impossible); a writer that attaches an EXISTING blob re-reads the row under that same guard and refuses unless it is `ready`. States are exactly `ready` / `deleting` / `broken` — `preparing` is an API word derived from the live supervisor, never a stored one. ⚠️ **There is deliberately no `ref_count`**: the owners are every row of BOTH queues in any status plus the live pins a capture, a dispatch or a backup holds, re-checked under the guard immediately before the unlink; `unreferenced_at` is a grace hint, never on its own a licence to delete. The refusals are a closed taxonomy answered verbatim — `503` `source_copy_busy`, `422` unreadable / changed / not a valid container, `504` timeout, `507` out of space — and no route invents a status beside them. ⚠️ The archive keeps the two hashes apart: the **unpatched** snapshot is the archive's source, the patched artifact is what was dispatched, and a snapshot never creates a `PrintArchive` by itself. ⚠️ SQLite ignores `ondelete`, so detaching a source from its jobs is done in code. A new construction site that forgets to name a source is a red build, not a silent regression: `tests/unit/test_every_queue_row_names_its_source.py` walks the AST of every writer (one allowlisted exemption, calibration prints). ## Failed AutoQueue print work returns only from positive live settlement

A successful addressed terminal commit and normal critical completion tail can publish a ready receipt; terminal status, age, reconciliation and cleanup alone cannot. One guarded return keeps the old failed row, per-print archive, costs and physical debt, and re-arms only its matching logical ancestor with an irreversible proof and bounded count. Caller cancellation cannot detach admitted I/O/SQL; restore requires a proven drain. Routing still considers its existing candidates and never waits for a busy alternative. An eligible attempt that published no start returns in its own addressed failure transaction under archive → lane → order → job → ancestor guards (G03 B2, §B). On PostgreSQL the order check tries `NOWAIT` under the guards. On contention the failure writer rolls the transaction back, releases its guards, waits for the order alone, and reruns the original claim or V3 proof. Archive filing can hold the order before asking for the archive. The failure writer keeps the printer halted and records a separate receipt and count of at most two. The settlement pass and toggle apply to physically failed prints. Vault: `40-invariants/inv-autoqueue-failed-return-needs-live-settlement.md`.

## AutoQueue notification identity is an observed fact, never display text

Eligibility carries immutable machine facts beside the human reason. Routine busy/conflict/copy-capacity waits remain visible without a waiting event. ## Operator print-state recovery is addressed and never replays completion

`services/print_state_recovery.py` alone decides which structural changes are proven safe; GET, preview and apply use that same policy. `print_state_recovery_store` revalidates a signed, process/storage-bound preview under archive → queue → item guards, changes only its named records, and commits the audit with the change. Operator recovery and terminal autorepair use `queue_ops.claim_lanes`: ALL local archive locks, then ALL local lane locks, precede SQLite's writer; PostgreSQL takes archive guards before lane guards and rows in that order too. An AutoQueue writer abandons a locally busy SQLite lane instead of waiting while it owns the writer. Inactive queues stay paused; a positively identified newer run and its header stay untouched. Estimated end times remain labelled and cannot justify deletion. A delete requires a proven completed execution and no dependent AutoQueue/calibration/receipt/order records, never `detach_print_queue_refs`; ambiguous cases have no force path. No physical commands, gate clearing, completion callbacks, accounting replay or source-file deletion belong to operator recovery. The standalone action on process memory, `clear_terminal_runtime_context`, commits its intent and the queue's pause (`is_paused` only, never `status`) first, then — under the same guards, rights, epoch and expiry rechecked — compare-and-clears exactly one finished run with its proven start and the two registrations its dispatch made (`services/runtime_context_release.py`: check everything, then change everything), and records the outcome; the effect generation never advances, a refusal keeps the pause, a replay never clears twice, and an unrecorded outcome is reported as such. An explicit operator close of one stopped printing execution requires stable fresh IDLE, proven ownership and an interrupted/unknown outcome. Its terminal rows and audit commit together without good-output credit; only then may the captured RAM context be compare-and-cleared, leaving a changed successor alone. Under the same synchronous proof, only the closed archive UUID's in-memory usage session may be discarded without accounting or durable cleanup. The release outcome is response-only; failures cannot turn a committed close into HTTP 500, and replay never repeats the release. A swap CLAIM (`owed` / `attempted` / `failed`) still blocks the close; the pending swap-macro list does not — dispatch writes it and only the completion handler removes it, so it stands on every stopped print of a swap-mode printer and is a request, not a debt (`runtime_effect_debt(..., intents=False)`); the close drops the list and records it in `operator_interrupted_print.swap_macros_not_run` (owner, 2026-11-18). ## A source's swap declaration is a captured fact with one reader and one writer (swap-source-lifecycle, 2026-10-14)

Whether a file carries its own plate-swap sequence is True / False / unknown — False is as authoritative as True, unknown is never False. Only a NEW external file is classified, by its own basename (`swap_compatibility.classify_external_name`: dot-delimited `.swap.` / `.swaps.`), at every door it comes in by (upload, ZIP member, scan, VP, MakerWorld, printer file); a rename declares nothing, a scan reclassifies only a new content identity, our own slices are False, and save-to-library carries the archive's confirmed fact or 409s (`swap_source_unknown` / `swap_source_conflict`). A job captures the fact with its bytes (`SourceFact` in `source_snapshot`; a pre-fix snapshot answers only through its own FK + matching hash, §6). An archive's record lives in `extra_data` (`swap_compatibility.CARRIER_KEY`) with the bool column as a projection: only `write_archive_fact` writes it, only `archive_fact` reads it, and a record-less archive is unknown except a strict True column; a library row declares only with a valid hash (`library_fact`), and a scan is never complete without one. Our swap macros over an unknown source with an effective request are refused (409 new, failed-before-dispatch stored), never guessed; True mutes them and narrows the printer list; the dialog's opt-out is per job, never a preference. At completion (`services/swap_terminal.py`, one fresh read after the last-chance attach) a baked sequence clears the plate only for a proven run — an accepted bound terminal of a proven origin (`print_run_binding.origin_is_proven`), completed by the RAW status, strictly True, not auto-eject — and our owed `swap_mode_change_table` runs (live and in the sweep) over a known False for the completed, persisted queue execution still owning the printer. A restart, reconnect, absent runtime binding or `observed` origin never revokes that saved obligation; origin proof applies to baked-file clearance, not this macro. Both paths recheck the execution and take the durable once-only claim before sending; anything else HOLDS: nothing sent, the event stays owed, no clear, the queue paused with a reason on the run's row, the next job and the archive (`swap_hold`), saying whether the cycle started (dispatch records `swap_start_effect`). The command goes out at most once (Codex review r1): one claim per execution archive in `bamdude_terminal_effects["swap_change_table"]` — `owed` (written by the sweep's close of a still-printing run with no accepted finish), compare-and-set to `attempted` and committed BEFORE the command under `queue_claim_scope` + `archive_write_scope` (`swap_terminal.claim_change_table`; the live path may claim over absent|owed, the sweep only over owed), `finished`/`failed` written with the event's removal (`finish_change_table`); a claim another owner in this process is sending is left alone, any other non-owed claim holds (`swap_hold_attempt_unknown`), never a retry. The run proof is the exact queue claim (printing this run, same start token), asked in the CAS and again before any release/pause/cleanup — a run that lost its queue writes only its own history. Every error holds; the connect edge also settles a completed run still holding its printer with the swap unsettled; both closes re-read under the writer and close nothing twice. A finish the live path accepted but never finalised is an uncertain outcome, and a swap that ran clears an earlier `swap_hold`. The held row's life ends once ANOTHER print has started on that printer — the hold can never settle after that: `services/queue_leftovers.py` retires such a superseded finished row with its router row (connect-edge sweep, after every completion, the Info page's Queue leftovers panel), never one its plate gate, an `owed` claim, its queue's current item or a missing archive copy still needs, and leaves the archive's `swap_hold` as history (2026-11-01). `tests/unit/test_swap_fact_has_one_reader_and_writer.py` fails on any other touch of the fact. ## An operator's swap declaration is bound to the bytes it was made for, and reaches only the jobs selected for it (swap-source-declaration, T9, 2026-10-14)
