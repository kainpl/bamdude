# CLAUDE.md

Guidance for coding agents working in this repository. Claude Code reads this
file on its own; `AGENTS.md` points other tools here. Everything below is about
the codebase — how it is built, what must not be broken, how a change is done
end to end — and none of it is Claude-specific. A maintainer's personal context
(local checkouts, knowledge-base wiring, paused work) lives in `CLAUDE.local.md`,
which is not in the repository.

## Project

BamDude — self-hosted print archive + farm management for Bambu Lab. Hard fork of Bambuddy. Python 3.12 / FastAPI · React 19 / TS / Tailwind 4 · SQLite or PostgreSQL · MQTT · aiogram 3.x. en+uk locales.

Architecture rationale, rejected alternatives and the "why" behind every
invariant below are recorded in a separate Obsidian vault (`bamdude.obsidian`,

[graphify](https://pypi.org/project/graphifyy/) installed, gunzip it to

Two traps, both silent: the build context is the fork's **GitHub URL**, not the local checkout; and the version lives in **both** `docker-compose.yml` and `.env`, where `.env` wins. ⚠ **`npx tsc --noEmit` is a silent no-op here.** The root `tsconfig.json` is `"files": []` plus project references, so without `-b` the compiler enters no file and exits 0 on anything — including a file whose only line is `export const x: number = NOT_DEFINED_ANYWHERE;` (measured 2026-07-28). Always `npm run typecheck` (`tsc -b --noEmit`). A refactor that dropped an import passed a bare `tsc` run and surfaced only as a blank dialog under vitest. ⚠ The pre-commit hook checks the **app** project only (`tsc -b tsconfig.app.json`, ~43 s, keeps commits fast); `npm run typecheck` also enters `src/__tests__` — run it before claiming green. Since 2026-09-04 the root references `tsconfig.test.json` too, so `src/__tests__` is type-checked as well — the run costs ~2× (a second full program over the same `src` graph), and a fixture that has drifted from its wire type now fails the check instead of only vitest.

## Architecture

**Backend `backend/app/`:** `main.py` (FastAPI factory + lifespan + global state dicts `_active_prints`/`_expected_prints`). `api/routes/` (every router registered in `main.py`). `services/` (printer_manager, bambu_mqtt, telegram_bot, notification_service, background_dispatch, archive, virtual_printer/, obico_detection). `services/telegram_handlers/` (aiogram FSM + `auth_middleware.py`). `models/` (async SQLAlchemy) + `schemas/` (Pydantic). `core/` (config, database, auth, permissions, encryption, rate_limit, websocket). `migrations/m000_*..mNNN_*` auto-discovered. `i18n/` + `data/` (en/uk JSONs: `telegram_ui`, `notification_templates`, `maintenance_types`).

**Frontend `frontend/src/`:** React 19 + Router 7 + TanStack Query 5. `api/client.ts` is **fetch-based, NOT Axios** — single `request<T>()` helper; binary endpoints call `fetch` directly. `i18n/locales/{en,uk}.ts` keys must match. Three.js for 3D viewer. **Production bundle tracked under `static/`** — source + bundle ship same commit.

**DB:** SQLAlchemy 2.0 async (aiosqlite/asyncpg). SQLite: WAL + 15s busy + NORMAL sync. `init_db()` = `create_all()` + pending migrations. `DEBUG=true` re-runs latest migration on startup.

## Migrations

Startup: `init_db()` → legacy `bambuddy.db` rename → `Base.metadata.create_all()` (idempotent) → SQLite→PG auto-migrate (if PG empty) → `_ensure_migrations_table` → `_bootstrap_existing` (marks m000+m001 applied for legacy) → `_run_pending` → `conform_imported_schema` (only after an import in this process).

⚠️ **The SQLite→PG move imports the file AS IS at ITS migration level, `_migrations` included, and the chain resumes at N+1** (`db_portable._reflect_sqlite_schema`; 2026-09-09). Never build the target schema from `Base.metadata` before the load — the models lack exactly the legacy columns/tables the later converters read (m157 `printer_id`, m158 project pivots), and re-running the whole chain on PG is how a dialect bug in an old migration reached a tester while the maintainer's own SQLite→PG path never executed it. What no migration ever did on SQLite (FK rules, NOT NULL, UNIQUE, CHECK, m001's tsvector half) is added once, after the chain, by `conform_imported_schema` — never on an ordinary boot. Model columns marked `info={"migration_shim": True}` (notification.py) are not canon and are skipped there. Vault: `40-invariants/inv-sqlite-move-imports-file-as-is.md`.

Each `mNNN_*.py` has `version`, `name`, `async def upgrade(conn)` (DDL), optional `async def seed(session_factory)` (DML). Helpers in `helpers.py`: `add_column`, `column_exists`, `table_exists`, `recreate_table`. Per-migration rationale lives in migration docstring — read there, don't duplicate here.

**Adding a column = TWO places:** model file (fresh installs via `create_all`) + new migration via `add_column()` (existing DBs).

## Key Invariants

**Auth always-on.** Every endpoint via `RequirePermission(Permission.X)`. Setup-gate middleware returns `503 setup_required` until `POST /auth/setup` creates admin (whitelist: `/auth/status`, `/auth/setup`, `/system/health`). API keys (`X-API-Key` / `Bearer bb_...`) bypass JWT but satisfy perms. Recovery: `python -m backend.app.cli reset_admin`.

**JWT + sliding refresh.** Access JWT has `jti` + `iat` (1h TTL); `/logout` revokes via `auth_ephemeral_tokens`. Password change stamps `user.password_changed_at` — older `iat` rejected. Refresh: SHA-256-hashed, HttpOnly + SameSite=Lax + Path=/api/v1/auth (`bamdude_refresh`), Secure auto from scheme, rotating with `family_id`; reuse collapses family. Frontend auto-retries 401 via `/auth/refresh` (coalesced).

**2FA + OIDC.** TOTP + email OTP + 10 backup codes. Login returns `requires_2fa=True` + `pre_auth_token` when enabled. OIDC: PKCE S256 + state + nonce + JWKS; SSRF guards reject non-HTTPS/loopback/private/link-local. TOTP secrets + OIDC `client_secret` Fernet-encrypted; `MFA_ENCRYPTION_KEY` auto-bootstraps (env → `DATA_DIR/.mfa_encryption_key` → generated, mode 0600). Backup ZIP packages key alongside DB.

**Rate limiting.** Sliding-window in `auth_rate_limit_events`. Login 10/15min per user + 20/15min per IP. Behind proxy: set `TRUSTED_PROXY_IPS`.

**Permissions.** `resource:action` (`printers:control` etc.) in `core/permissions.py`. Default groups: Administrators / Operators / Viewers. **API-key scopes** confine a key's reach: `core/auth.py` maps every `Permission` either to a `can_*` column in `_APIKEY_SCOPE_BY_PERMISSION` (`can_manage_library`/`inventory`/`projects`/`archives`/`maintenance`, `can_queue`, `can_read_status`, …) or onto `_APIKEY_DENIED_PERMISSIONS` (admin-only — e.g. `ARCHIVES_PURGE`/`LIBRARY_PURGE`/`PIPELINES_WRITE`). **Every new `Permission` MUST land in exactly one** (a drift-guard test enforces it) **and be seeded to Administrators in its migration** (O2 discipline — Administrators aren't self-healed at startup, our migrations are frozen).

**Telegram dispatch authority is the chat (m045+).** `NotificationProvider` rows of `provider_type='telegram'` keep only `enabled` + `daily_digest_*` + token + name (+ `printer_id`). The 24 `on_*` flags + `quiet_hours_*` are forced True/False by m045 + `_coerce_telegram_provider_fields`. Per-chat `TelegramChat.{notify_events, quiet_hours_*, daily_digest}` is sole authority. **Never reintroduce a provider-level event toggle for telegram.**

**Macros.** GCode via MQTT `gcode_line` wrapped with `M1002 gcode_claim_action:0/idle`. `services/macro_executor.py` + `PrinterManager.execute_macro_and_wait`. Swap macros auto-fire from `background_dispatch`. `action_type='mqtt_action'` (m017+) routes via `core/mqtt_macro_actions.py` + `services/macro_trigger.py`.

**Single dispatch layer.** Only `background_dispatch` runs prints. `print_scheduler._start_print` is a thin wrapper. Dispatcher creates exactly one archive per physical print, wires `PrintQueueItem.archive_id` in same txn, signals via `PrintDispatchJob.completion_event`. External prints (printer screen / Send-to-Printer) create their archive in `on_print_start`, at print start — see *The archive row is created at PRINT START* below.

**Archived printers (soft-retire, m105).** `Printer.archived` + `archived_at` — an INDEPENDENT axis from `is_active` (Maintenance Mode): maintenance parks temporarily + keeps the card visible; archive retires + hides everywhere, history preserved. "Available" = `is_active AND NOT archived` — the `Printer.archived.is_(False)` filter sits beside **every** `is_active==True` availability query (MQTT connect loop, scheduler, `auto_queue_eligibility.find_eligible_printer`, metrics, pipelines, VP, telegram, …) **and** the queue-list endpoint (`printer_queues.list_queues`). `GET /printers/` excludes archived unless `?include_archived`; keep the frontend `getPrinters()` **param-free** (a separate `getPrintersWithArchived()` feeds the restore section + Archives filter — an optional arg breaks TanStack's `queryFn: api.getPrinters` inference). `POST /printers/{id}/archive` (PRINTERS_DELETE) blocks while `is_print_active` (409), cancels the printer's pending `print_queue` items, disconnects MQTT. Restore/delete under Settings → Printing → Archived printers.

**Preheat / heat-soak stage (opt-in, #1468).** Between FTP upload and `start_print`, `services/preheat.py::preheat_and_soak` (invoked from `background_dispatch` in both `_run_*` branches) heats bed + chamber and holds at temp — firmware ignores `M191`, so the soak is orchestrated here. Per-print chamber target = max across loaded AMS slots via `DEFAULT_PREHEAT_FILAMENT_TARGETS`; three hardware tiers gated by `supports_chamber_heater` / `supports_airduct` (active `M141` / sensor-wait / timer) with airduct-flap flip. Per-print override in `PrintQueueItem.preheat_override` (+ `preheat_chamber_target_override`) threaded via `job.options`. Cancel-aware. Off by default (`preheat_enabled`).

**3MF gcode patcher.** `services/gcode_patcher.py::apply_3mf_transforms` comments `M970`/`M970.3` when `mesh_mode_fast_check=False` and applies gcode injection in ONE open/mutate/write cycle; recalcs `.gcode.md5` sidecars. (The single-purpose `patch_mesh_mode_fast_check` it superseded lost its last caller in that refactor and was deleted 2026-08-06.) **On-disk archive always unpatched** — patched copy → FTP via /tmp, dispatcher cleans up. `applied_patches` is informational; never read to infer disk state. `scripts/prune_orphan_archive_files.py` reconciles disk vs `print_archives.{file_path,thumbnail_path}` + `library_files`.

**Archive chain-of-custody (m009+m039).** `source_content_hash` (SHA256 of unpatched root) + `content_hash` (SHA256 of FTP'd bytes) + `applied_patches` JSON. Invariant: every row has non-NULL `source_content_hash`. `effective_hash = COALESCE(source_content_hash, content_hash)` is disk-dedup key (cross-printer). Hard-delete ref-counts shared `file_path`s; `rmtree` only on last reference. Forensic queries use `content_hash` (distinct per applied-patch outcome).

**3MF copy is fsync'd.** `archive.py::_copy_and_fsync` replaces `shutil.copy2` (sendfile silently truncated 3MFs on armv7l/bookworm — #1032). ZIP-validity check post-copy. Folder `YYYYMMDD_HHMMSS_<stem>` with `_2,_3` suffix on collision; `mkdir(parents=True)` no `exist_ok` so races fail loudly.

**VP FTP needs the asyncio loop.** `uvicorn[standard]` auto-selects uvloop, whose TLS layer can silently truncate a 3MF uploaded to the virtual printer on a ragged EOF (#1896). **Every native launch path passes `--loop asyncio`** (Dockerfile, `install/install.sh` systemd+launchd, `deploy/bamdude.service`, Windows NSSM/`install-service.bat`) — never drop it. Defense-in-depth: `virtual_printer/ftp_server.py::cmd_STOR` ZIP-validates a `.3mf` before ACKing (426 on truncation, no fallback archive of a broken job).

**The archive row is created at PRINT START, before the 3MF** (`on_print_start`, `file_path=""`), and the file is attached later via `attach_3mf_to_archive`. Everything time-sensitive moves with the row — `_active_prints`, `_record_energy_start`, the start notification, queue-busy, timelapse session + baseline. ⚠️ **Spoolman tracking deliberately does NOT** — with an empty `file_path`, `store_print_data` takes its degraded remain%-delta path. ⚠️ Two post-download branches can still adopt an existing archive (plate-corrected re-download, content-hash adoption); the speculative row must be deleted there or one print gets two rows. ⚠️ `attach_3mf_to_archive` must fill everything `archive_print` fills — it is now every external print's path, not a rare recovery. ⚠️ **A print observed RUNNING on a fresh process with no live archive — started while BamDude was down — is adopted** by `on_print_running_observed` → `_adopt_running_print` (2026-09-12): the same provisional row with `started_at=None` and `extra_data["recovered_start"]={observed_at, remaining_seconds}`, filled by `attach_3mf_to_archive` as `observed_at − (estimate − remaining)` once the 3MF lands (attach never overwrites a start it was given; a malformed record leaves it unknown), energy banked and marked `energy_is_approximate` + `energy_start_partial` (the counter covers only the remainder), usage session CREATED (not restored — `on_ams_change` would otherwise sync remain% weights until completion and the write-off would count the first half twice), queue row claimed, cover cache cleared; the download runs in a tracked task under `archive_download_retry.claim`, hashes BEFORE attaching and asks `_find_live_hash_twin` (the one predicate `on_print_start`'s restart-recovery block uses too) — a twin inherits the energy baseline and the provisional row is discarded; otherwise the task mirrors `on_print_start`'s tail, split by what needs the file: loaded-spool colours re-applied and objects into state follow a SUCCESSFUL attach, while `_store_spoolman_print_data` follows the download's OUTCOME whatever it was (no 3MF on locked-file firmware, or a failed attach, stores on the row's empty `file_path` — the degraded remain%-delta path — because the print ran either way; only the twin path skips it, that row having had its own tracking since dispatch). Nothing notifies — no start notification, `print_started` macros, plate check, plug action or missing-spool prompt. The #1304 guard stays; only the print running now is recoverable.

**3MF download recovery.** Empty `file_path` = the retry marker. `extra_data["no_3mf_available"]` means "we tried and failed" and is set ONLY after a failed attempt — it raises a user-facing banner, so never set it optimistically. `services/archive_download_retry.py` fills via 4 triggers: startup sweep, printer reconnect, `on_print_complete` last-chance, manual `POST /archives/{id}/retry-download`. ⚠️ `on_print_start` holds the same per-archive guard via `claim()` for its own download, or a mid-download reconnect attaches a second copy over the first. ⚠️ `ftp_timeout` bounds a **stalled** socket, not a slow transfer. Temp: `archive_dir/temp/<printer_id>/<filename>`. ⚠️ `services/archive.py::find_archive_for_sd_file` is the single «file name on the printer's card → archive» resolver (newest row with its 3MF OR its extracted PNG on disk — a retention-cleaned row keeps its picture by the 2026-09-12 ruling; pending and trashed rows never answer): the printer-card cover and the file manager's plates both ask it, and nothing re-implements the match.

**Camera stream-token.** Stream/snapshot/cover need 60-min token from `POST /printers/camera/stream-token`. `<img src>` can't send Auth headers → `withStreamToken()` threads token via query param. `useStreamTokenSync` keys cache on `user.id`; `rewriteMediaSrcWithToken(root, token)` retrofits already-rendered media.

**Obico AI failure detection (opt-in).** `services/obico_detection.py` polls RUNNING printers every 5–120s. JPEG cached under 32-byte nonce (30s TTL); Obico ML gets URL to `/api/v1/obico/cached-frame/{nonce}` (whitelisted in `auth_middleware`). EWM + dual rolling-mean → `safe`/`warning`/`failure`. Actions: notify / pause (MQTT) / pause_and_off (MQTT+smart-plug).

**CSP + security headers.** `security_headers_middleware` registered AFTER `auth_middleware` so it wraps 401/503. `script-src 'self'`; `connect-src 'self' ws: wss:`; `frame-src 'self' https:`; `frame-ancestors 'none'`. HSTS on HTTPS. `/sw-register.js` served by `serve_sw_register()` so strict `script-src 'self'` holds.

**Manual jog mirrors BambuStudio, never disables endstops.** `bed_jog` emits BS's own sequence byte-for-byte (`temp/references/BambuStudio/src/slic3r/GUI/DeviceCore/DevAxisCtrl.cpp:49`): `M211 S` → `M211 X1 Y1 Z1` → `M1002 push_ref_mode` → `G91`/`G1` → `M1002 pop_ref_mode` → `M211 R`. **Never emit `M211 S0`** — that form doesn't exist in Bambu's dialect (bare `M211 S` is *push*, `M211 R` is *pop*), and Bambu's own sliced start G-code leaves the soft endstops OFF, which is why BS re-enables them before every jog. There is deliberately no trailing `G90` (pop_ref_mode restores it) and no `force` param. The not-homed modal stays — but ⚠️ **not because BS refuses an unhomed jog; it does not.** `StatusPanel::check_axis_z_at_home` is called *after* `Ctrl_Axis` has already published, so BS sends the Z move and then pops a recenter dialog. Our modal is a deliberate divergence (an HTTP surface reachable from another room is not a desktop window in front of the machine), and #2579 removed "Move anyway" because it drove the move with the soft endstops disabled. Don't "restore parity" here. The #1334 bed-slinger Z-sign flip is safety-critical — BS corroborates it at `DevAxisCtrl.cpp:39-44`.

**Plate selection in 3MF parsing walks child metadata.** Bambu identifies a plate with `<metadata key="index" value="N"/>` **inside** `<plate>`, NOT a `plate_idx` attribute. `ThreeMFParser` and `extract_printable_objects_from_3mf` must agree; a `.//plate[@plate_idx=…]` lookup silently misses and falls back to plate 1, which made `plate_number` inert for months and let Skip Objects cancel the wrong part on multi-plate jobs. Always pass the plate: `resolve_plate_id(client.state)` on live paths, `archive.plate_index` on archive paths.

**Portable backup carries canonical DDL and migration history.** `db_portable._export_pg_to_sqlite` creates a separate SQLite metadata copy, omitting `migration_shim` bootstrap columns without mutating global models. Never replace full DDL with hand-written name/type tables. `_migrations` must travel with the rows; SQLite FTS is rebuilt without replaying baseline migrations. PostgreSQL export reads one read-only snapshot and refuses unhandled source schema; SQLite export uses the online backup API, including WAL. Only completed files replace the destination. NULL coalescing uses Python defaults or datetime server-defaults, never guessed boolean/integer SQL defaults. Vault: `40-invariants/inv-portable-backup-full-ddl.md`.

**Backup file copying is strict.** `backup_files.directories()` is the shared path map (including configured archive/calibration roots); empty directories are included. Source changes, unreadable files and an existing corrupt Zigbee DB fail the backup. New ZIPs carry a size/SHA-256/directory manifest; old ZIPs still get path/CRC/DB validation. Reject links/junctions, duplicate paths and traversal. Filesystem workers must be awaited even on cancellation; backup/restore share a process lock. Stop Zigbee cleanly before replacing its database/sidecars. Vault: `60-specs/backup-files-spec-plan.md`.

**Portable restore preserves the previous database on import failure.** Validate the SQLite file before restore side effects. PostgreSQL DROP, CREATE, load, sequences and FK restoration share ONE transaction; FK repair uses savepoints within it, and conflicting rows must not be silently skipped. The source file still owns its schema/migration level. Release the request's session before DROP. `backup_files.FileRestore` stages and verifies ALL incoming files on their destination filesystems, retains old contents without replacing mount roots, and rolls back file moves if replacement of the DB fails. Commit file state immediately after DB success (inside the SQLite worker, to survive cancellation); later migrations must see matching new DB and files. A failed rollback retains recovery copies, never deletes them. The whole ZIP is not a power-loss-safe distributed transaction. Vault: `40-invariants/inv-portable-restore-transaction.md`.

**Bulk inventory actions are selection-scoped, never filter-scoped.** Row checkboxes drive Edit / Print labels / Reset usage / Archive / Restore / Delete; "act on the whole filter" exists only as an explicit **Select all N matching the filter** action. The header checkbox ticks **visible rows only**. Selection auto-clears on any filter/search/tab/grouping change. `BulkEditSpoolsModal` shows a **read-only** list of what will change — it must never regain its own checkboxes, which would be a second source of truth for the same question.

**Dispatch is claimed per PRINTER, not per item.** `set_queue_busy()` flips `PrinterQueue.status='printing'` and `print_scheduler` seeds `busy_printers` from it; `_dispatch_holds` adds an in-memory post-dispatch window. ⚠️ **Every print now also holds a queue ROW while it runs** — direct prints take it at dispatch (`queue_batch.claim_printer_for_direct_print`, `status='printing'`, `position=0`), external ones at print start (`mark_queue_printing_for_printer`); the dispatcher owns the release. Before that, a "print now" claimed nothing until the printer had already started, so the queue saw an idle printer for the whole upload and dispatched over the job (0.5.4). "Queue item" therefore no longer means "work somebody queued". Upstream's per-item `dispatching_at` is deliberately NOT ported — it would be a second, weaker source of truth. **This DB claim is what serialises tier 1**: `on_print_complete` runs the swap macro *inside itself* and only then calls `set_queue_idle`, so the printer stays claimed across the whole plate change whatever the live MQTT says. The swap wrapper moves `stg_cur`, completion keys off `gcode_state` — different fields, so a macro can never be mistaken for a print ending.

**Routing is NOT dispatching (auto-queue).** `find_eligible_printer` must never gate on *readiness* — plate-clear gate, drying, stagger are `check_queue`'s questions, asked again at dispatch. Readiness only **ranks** candidates there (ready wins, busy still gets work). Gating at routing time doesn't make anything safer: the item just waits in the printer's queue visibly instead. It DID make an idle farm report `Busy: …` with an empty per-printer queue and therefore no Clear Plate prompt — that prompt renders off the queue auto-queue was refusing to fill. Keep the busy set (`status='printing'` OR any pending item) and the filament/colour match; those are routing questions.

**Rebalancing moves only PENDING line work, and a move is all-or-nothing (spec 2026-09-10).** `services/queue_rebalance.py` may convert an auto-queue row in place and create its `k−1` companions through `add_items_to_auto_queue` — never a per-printer row, never an assigned / scheduled / staged / pinned / located / archive-sourced / un-filed one (`refusal`; the closed `SKIP_REASONS` list is mirrored by `autoQueue.rebalance.skipped.*` in both locales). The target plate and the receiving model's profile are read BEFORE the first write, and a writer refusal restores the row field by field (`creation_failed`): a lone converted row would silently under-cover its line. "Idle" is asked only to pick who RECEIVES moved work (the tick's busy set via `auto_queue_eligibility.busy_printer_ids`, AND `_is_printer_idle(pid, require_plate_clear=True)`, AND a queue `check_queue` will actually dispatch from — status not `paused`/`error`), which keeps *Routing is NOT dispatching* intact on both sides — the router is never gated, and work never moves to a printer that only looks free. The tick hook runs after the placement pass and before its commit, behind `auto_queue_rebalance_models` (default off) with a per-line cooldown; both manual routes force. Vault: `20-systems/print-queue.md` §Перебалансування, `40-invariants/inv-rebalance-moves-only-pending-line-work.md`.

**A job that has been sent but not started is not an orphan.** `print_reconciliation` re-arms on every MQTT client recreation (#1542) and the dispatcher itself triggers reconnects via `ensure_fresh_connection_for_printer` — so the sweep lands mid-dispatch routinely. Guard on `PrintArchive.created_at` (`_JUST_DISPATCHED_SECONDS`), **not** on `_dispatch_holds`: the hold is registered only after a *successful* dispatch, which is seconds too late. Symptom when broken: queue item marked completed before its own archive starts, its row and its `auto_queue_items` partner left behind (auto-clean lives in `on_print_complete`, which never ran).

**A long walk holds neither the transaction nor the loop (m148).** External-folder scanning lives in `services/library_scan.py`: stat / hash / 3MF parse happen with **no session open** and off the event loop via `to_thread`; writes go in `BATCH_SIZE` chunks, each its own short transaction (sized for *lock time*, not commit cost — WAL + `synchronous=NORMAL` means a commit costs no fsync). Doing it the old way took SQLite's write lock from the first `flush` to the final `commit` with a whole NAS walk in between, and unrelated queries died with `database is locked` naming an innocent victim. ⚠️ **Therefore the request cannot wait for the result** — `POST /library/folders/{id}/scan` answers `202 {job_id}`, never counts; progress rides the socket, the summary is the `library_scan_jobs` row. ⚠️ **Reachability is checked in the worker, not the handler** (`Path.exists()` blocks on a hung mount). ⚠️ **Short transactions cost the rollback that used to make a failed scan harmless** — so `remove_vanished` refuses every deletion when the walk came back empty against a stocked folder (`EMPTY_WALK_GUARD = 1`, `skipped_deletions=True`, reported on screen): an unreachable share is indistinguishable from a folder somebody emptied. ⚠️ **Ending a scan is TWO halves** — the row *and* the socket; `_fail_job` does both, and the event carries `folder_id` or the strip it should clear cannot be found. ⚠️ FK `ON DELETE CASCADE` on the job rows is honoured by PostgreSQL only — this codebase never sets `PRAGMA foreign_keys = ON`.

**Free stock of product parts is a LEDGER with one writer (m162).** `product_part_stock_movements` holds signed movements per product part (`surplus_banked` · `unfiled_print` · `reserved_for_order` · `reservation_released` · `manual`); the balance is Σ delta, never a column. **Only `services/part_stock.py` writes the table** — routes, `on_print_complete`'s `_credit_free_stock` hook and the part/product delete–merge paths call it; readers may live anywhere. The writer never writes a zero row, enforces the sign per reason, locks the part row for its read-decide-write (`lock_part_stmt`, `populate_existing`) and refuses a balance below zero (`PartStockError` → 409). Two rules the user chose: an order's surplus goes to stock only by the **button** (`POST /projects/{id}/bank-surplus`, differences only); an order-less completed print goes to stock **automatically** (idempotent by the archive's NET); filing it under an order later reverses the credit, un-filing re-credits (symmetric). A line reserves whole kits, clamped to `min(asked, quantity, kits_available)`; every "still needed" figure subtracts the reservation and the order-level sum caps it per line. ⚠️ SQLite ignores FK actions — CASCADE/SET NULL are done in code through the writer (`delete_for_part(s)`, `repoint`, `detach_archive`, `detach_line`). ⚠️ Backend-written notes are tokens from `NOTE_TOKENS` (the frontend translates them); free text is the operator's `manual` adjustment only. Vault: `20-systems/products.md` §Залишок, `40-invariants/inv-stock-ledger-single-writer.md`.

**Defects have one writer, and the shelf follows them (2026-09-11).** `services/archive_defects.py::record_defects` is the only thing that sets `PrintArchive.defective_count` / `print_archive_parts.defective` (the pre-existing Skip Objects hook and the m158 row-seeding rule stay): a per-part value is absolute and clamped to the row, `defective_count` is the SUM of the rows when rows exist — a flat count sent alongside rows is ignored — else the clamped flat value. Four doors call it: `PATCH /archives/{id}`; the order page (`POST /projects/{id}/archives/{archive_id}/defects`, `PROJECTS_UPDATE`); both plate answers (`clear-plate` / `repeat-print` with an optional `defects` body under `PRINTERS_CLEAR_PLATE` — the waiting archive is resolved BEFORE the answer releases the hold row, and the helper never commits, so a refused repeat rolls the defects back); and the Telegram prompt (`telegram_handlers/defects.py`, registered ABOVE `actions_router` because that router ends in a catch-all `action:` filter; the completion message's «Брак…» button carries the archive id threaded through `archive_data` → `extra_data` and is omitted when the completion could not be attached to an archive — never a "newest completed" guess, which pointed at the previous print). After the write the writer calls `part_stock.adjust_unfiled_print`: for an order-less completed print with a library file it writes `wanted − standing` per product part as `manual` + `archive_id` + `NOTE_DEFECTS_RECORDED`, only where `standing > 0`; an unresolvable `wanted` (`{}`) does nothing; a refusal below zero is RETURNED, never raised — the defects stay recorded (the archive is the print history) and the refusal is reported where it can happen (card toast, Telegram line; the order route never sees one — a filed print was never credited). ⚠️ `seed_archive_parts` applies a standing flat count to freshly seeded rows (`apply_flat_defective`, mono-plate rule): an external print completes before its 3MF arrives, so the flat count typed at plate-clear must survive the rows that come later. Vault: `40-invariants/inv-defects-single-writer.md`, `20-systems/archive.md` §Один писар браку, `20-systems/products.md` §Брак після кредиту.

**Staggered start is capped per GROUP, and an unassigned printer is a wildcard (m164).** A printer's stagger groups come from `services/stagger_groups.py` — its picked tags × the nearest picked location ancestor; the key is `(tag_id | None, location_id | None)` and both axes off is today's one bucket. **A printer with no picked tag (or no picked ancestor) is in EVERY group and starts only when all have room** — its phase is unknown, so it may be on any; this is also why enabling a split before tagging changes nothing. Slots never store groups: the resolver is loaded once per tick and re-asked, so a tag pinned mid-heat counts next tick. A printer never blocks itself (its own slot is excluded). **Strict mode for direct dispatch = refuse instead of wait**, decided in `background_dispatch._process_job` BEFORE the acquire, through the runner's four failure exits, leaving the queue idle; queue jobs are never refused. Tags are an entity (`printer_tags` + `printer_tag_links`, links written only by `services/printer_tag_service.py`; SQLite ignores the cascades); a tag or location that is a group returns 409 on delete. ⚠️ The model-import list lives ONCE, in `core/database.py::import_all_models`, shared by `init_db` and `tests/conftest.py::test_engine` (the copy conftest used to keep drifted) — a model missing there is invisible to the app AND to every test; `tests/unit/test_every_model_module_is_registered.py` compares it against the directory. Vault: `20-systems/staggered-start.md`, `40-invariants/inv-stagger-unassigned-is-wildcard.md`, `20-systems/printer-tags.md`.

**A printer's queue is the `printer_queues` row with the printer's own id — always.** `PrinterQueue.id == printer_id` is an invariant the scheduler leans on everywhere (`item.queue_id` is read as the printer id), and `services/printer_queues.py::ensure_printer_queue` is the ONLY creator: it looks the row up by id first; an orphan of a deleted printer sitting on that id is adopted (stale items dropped), a live printer's queue misplaced under another id is re-keyed home (items + archives follow), and the startup sweep runs this for every printer. **Never create a `PrinterQueue` under "the next free id"** — d93977c8 did, and the user killed it the same day (2026-09-05). Vault: `40-invariants/inv-printer-queue-id-equals-printer-id.md`.

**API refusals are translated at the boundary, never at the raise site.** A route refuses with an English sentence (`HTTPException(409, detail="…")`) and knows nothing about language; one handler (`backend/app/i18n/api_errors.py`, installed right after `app = FastAPI(...)`) looks the sentence up in `data/api_errors_uk.json` — the English sentence IS the key, f-strings are `{}` templates matched by regex — and answers in the **system** language (`current_language()`, never `Accept-Language`). Never translated: `MACHINE_READ` (the 401 texts `api/client.ts` branches on), bare codes like `parts_not_editable` (`is_code`), and `str(e)` of foreign exceptions. Anything the frontend must *react* to travels as `{"error": code, "message": …}` (only `message` is translated; e.g. `not_sliced`); **never branch on `ApiError.message` text**. Hand-built refusals go through `json_error(status, detail)`, not a bare `JSONResponse`. Coverage is a test: `scripts/api_error_catalog.py sync` + `tests/unit/test_api_error_details_have_ukrainian.py` (AST scan; missing sentence, stale key or placeholder mismatch fails CI). Vault: `40-invariants/inv-api-refusals-translated-at-the-boundary.md`.

**Case folding is Unicode-aware on every backend, decided in `core/case_folding.py` — never in a route.** SQLite's built-in `lower()` folds ASCII only, and SQLAlchemy compiles `ilike` to `lower(col) LIKE lower(:q)` there, so `?q=ЛАМПА` never found «лампа»: every SQLite connection (`configure_sqlite_connection`, also attached by `tests/conftest.py`) shadows `lower`/`upper` with Python's. A PostgreSQL database created with `LC_CTYPE=C` folds ASCII only too (measured on the dev server): `init_db` probes once per boot, `reinitialize_database` again after a restore (`probe_postgres_case_folding` — `SELECT lower('Ж') = 'ж'`, then each candidate of `FOLD_COLLATIONS` is verified before it is trusted), and when the database cannot fold, the folding compiler (`case_folding.compiler_for` — the mixin laid over whatever statement compiler the driver's dialect carries, never assigned over it) renders `ilike`/`lower`/`upper` through `pg_c_utf8` (17+) or `und-x-icu`, and `routes/archives.py::_use_fts_search` takes the `ilike` branch only when a collation was chosen; with none, FTS stays on — neither the m001 tsvector nor `ilike` folds and the index is faster; a server with neither collation logs the cure (recreate the database with a UTF-8 locale). The FTS statement runs inside a SAVEPOINT (`db.begin_nested()`, never `db.rollback()`, and `matched_ids` is assigned only after the block exits) — a refused index query, and the search term is the user's, would otherwise abort the transaction and take the `ilike` fallback down with it. A folded lookup that finds several case-variant users — an install could hold `Ірина` and `ІРИНА` before the fold was Unicode — picks the exact-case match, else the oldest, and warns once (`core/auth.py::_pick_folded_match`); the duplicate checks read the first folded match and refuse as they always did (400 on user create/rename, 409 on LDAP provisioning), never 500. The bundled server (`--builtin-locale=C.UTF-8`) and the official Docker image fold natively and compile exactly as before. Uniqueness keys (`name_key`) are computed in Python and never depended on this. Vault: `40-invariants/inv-unicode-case-folding.md`.

**Modals close only by their buttons or Esc — never on a click outside.** Every modal renders through `components/Modal.tsx` (portal into `body`, z-index = 50 + its position in the modal stack — never hand-written, backdrop without a click handler, header X, `role="dialog"` + focus); `components/modalStack.ts` owns the ONE Escape listener (on `window`, not `document` — 12 tests dispatch there) and gives Esc to the topmost modal only, so a `ConfirmModal` over `PrintModal` closes alone. `modalStack` also owns every `inert` attribute of the modal layers — the focus trap: while the stack is non-empty `#root` is inert, and so is every overlay except the topmost, written imperatively in `register`/`unregister` (never a React prop), so the layer below is live again in the same cleanup pass in which `useDialogFocus` returns focus to it; `Modal.tsx` calls `useModalStackEntry` BEFORE `useDialogFocus` for exactly that reason (cleanups run in declaration order — `Modal.test.tsx` pins it). The hook reads the opener in a layout effect and returns focus in the passive cleanup — before the stack's passive effect can make `#root` inert, and after its cleanup has made it live again. Two modals unmounting in one commit clean up top-down, so the outer return is deferred by a microtask when the opener is still inside an inert subtree. Toasts are portalled into `body` because a viewport inside `#root` would be dead under a modal. A non-modal overlay inside `#root` stays BELOW the modal layer (`z-[49]` at most — `modalShellOwnership.test.ts` fails a `fixed` element at z ≥ 50 in a file that does not portal); at or above it the overlay is visible-but-dead under a modal. The menus that open dialogs from their items (CardActionMenu, TrashSplitButton, the file-manager menus) give focus back to their trigger on every close, so the dialog has a live element to return focus to; a popover that never opens a dialog does not need to. The stack is mount order with one correction carried by `ModalAncestryContext`: an ancestor that registers after its descendant (same-commit mount — React runs child effects first and lands portal children in `body` child-first) slides in just below it; nesting depth is deliberately NOT the order, because an app-level alert raised over a nested chain must sit on top of the chain. `variant="lightbox"` is the single sanctioned click-outside (a picture on a dark ground); a menu/popover/drawer/loading/viewer overlay that must dismiss on outside click says so with `// not-a-modal: <kind>` on the line above its tag. An Escape handler for an INNER layer (inline edit, dropdown) lives on `document` and stops propagation; page-level shortcut handlers check `isAnyModalOpen()` (Layout, KProfilesView, ArchivesPage) — `stopPropagation` cannot reach a sibling `window` listener. `__tests__/components/modalShellOwnership.test.ts` scans the sources and fails on any other full-screen overlay (any `bg-*` ground counts — the fullscreen camera is `bg-bambu-dark-secondary`) — a new modal that draws its own `fixed inset-0` is a red CI, not a style choice. `size` is a closed table (`xs…8xl`, `full`; `full` has no `max-h` cap); `8xl` exists only because `index.css` declares `--container-8xl`; computed geometry goes through `panelStyle` (inline beats every class — overriding the panel's base classes via `panelClassName` depends on Tailwind's emit order). `Layout` also swallows `dragover`/`drop` for `Files` drags app-wide: the old full-screen overlays were the only thing stopping a dropped file from navigating the browser away. Vault: `40-invariants/inv-modals-close-only-by-buttons-or-esc.md`.

**Async-first.** All I/O async. FastAPI `Depends()` for DI. Pair every `asyncio.create_task` with shutdown cancel. Autouse `_cancel_leaked_asyncio_tasks` drains pending tasks between tests.

**Labels are data, not layout code.** `label_templates` / `label_sheets` (m146) hold a design as a list of mm-positioned boxes; one walk (`label_canvas.draw_template`) feeds two backends — PDF and a 1-bit raster. Editor lives in Settings → Filament → Marking and NOWHERE else. Direct-to-device printing (m147, `label_devices`/`label_jobs`) has the server hold a queue a desktop bridge polls. ⚠️ The template is the truth and the cassette is the gate: a design is printed at its own size or refused, never scaled — fractional scaling of 1-bit destroys bar ratios silently. ⚠️ A built-in template and an un-adopted device are both frozen by design. Full detail: vault `20-systems/label-templates` + `20-systems/label-devices`.

**Color names — single source of truth.** `color_catalog` table; backend has no hardcoded tables. Frontend `ColorCatalogProvider` → `getColorName()` / `resolveSpoolColorName()` in `utils/colors.ts`. Bambu Lab wins on hex match; HSL fallback otherwise. **Never reintroduce hardcoded color tables** — suffix fallbacks structurally mislabel.

**Per-print energy.** `PrintArchive.energy_start_kwh` captured at print start (helper `_record_energy_start` in `main.py`); end-handler `_record_print_energy` (module-level, lifted out of `on_print_complete` to be testable) reads from fresh DB session, computes delta. **The END read is forced** — `_get_plug_energy(..., force_read=True)` → `service.refresh(plug)` for drivers flagged `reads_from_a_cache` (Zigbee only; HTTP/MQTT drivers are already live). The plug's counter moves only when it reports, ≥30 s apart, so an unforced final read systematically drops the last half-minute of a print, always in the same direction. Start is deliberately NOT forced: the same lag there covers an idle printer and cannot pay for a radio read on the dispatch path. The flag routes via a driver attribute, never `plug_type` — that if/elif is what `_get_plug_energy` exists to have removed. Restart-resilient — never in-memory dicts. Range stats via hourly snapshots in `smart_plug_energy_snapshots` + `_sum_snapshot_deltas()` in `archives.py`.

**The zigbee device-class set is closed** — smart plugs and sensors, nothing else. A new quantity is a ROW in `zigbee/measurements.py`, never a new class: the classes carry pairing, freshness and UI behaviour, and a third one means re-deciding all three for what is really just another reading.

**Measurement history is written ABOVE the plug drivers, never from a device listener.** `services/measurement_history.py` (driven by `smart_plug_manager._history_loop`) is the only writer of `smart_plug_power_history`; sensors reach `smart_sensor_history` the same way through `services/measurement_buffer.py`. Writing from the Zigbee listener would make an application feature exist only for one of the five plug types. **Hybrid by necessity:** zigbee and mqtt report, so every report is written; tasmota, rest and home_assistant never report at all — their only readings today are the hourly energy snapshot and *the frontend polling while a tab is open*, so their history would record when somebody was watching. Those three are sampled by the loop instead. The accepted consequence is that series density differs by plug type. Buffer first, flush later: both report callbacks are **synchronous** and must not raise (zigpy swallows listener exceptions at DEBUG), so a direct DB write would be a coroutine nobody awaits. There is deliberately **no de-duplication** — a flat line and a lost connection must not look alike. Pruning rides in the same loop that samples, so writing and pruning cannot survive each other.

**A switched-off plug reports 0 W, as physics — not as trust in the device.** `zigbee/driver.py::get_energy` returns `power: 0.0` whenever the known state is `OFF`, whatever the reading cache holds; an unknown state is NOT treated as off. Cheap plugs keep reporting the last measured watts/amps after the relay opens (S60ZBTPF pre-2.0.3 firmware did exactly that, and BamDude showed 33 W for an empty socket). The upstream quirk fixes only transitions it witnesses, so it cannot cover a restart. `total` is never zero-filled — a fabricated zero would be differenced as real consumption. **Zigbee quirks need two conditions, both silent when broken:** `ControllerApplication.new()` must get `device_resolver=` (without it zigpy applies NO quirks at all), and attribute values must come from `cluster.get(attr)`, never from what `read_attributes` returned (that is the raw pre-quirk value, and zigpy suppresses the update event for the attribute being read). Verify with `GET /zigbee/devices/{ieee}/attributes` — `device_class` must be `CustomZigpyDevice`, and raw vs cached diverge exactly where a quirk acted. **Reports arrive on `on_event`, never on `add_listener` alone** — zigpy 2.x delivers a reported attribute inside `_suppress_attribute_update_event`, so the legacy channel hears nothing at all; `reporting.py::_subscribe_cluster` is the single place both channels are wired, and a listener needs `__call__(event)` as well as `attribute_updated`. A stub that only has `add_listener` will confirm whatever wrong model you hold (it did, for 300+ green tests). The 30–45 s poll (`zigbee/poller.py`) is the **floor**, not the mechanism — measured 35 value changes in 3 min from reports vs ~5 from polling — and it stays because ZHA polls `ElectricalMeasurement` by default too (exempting 4 allowlisted models), while for `Metering` the rule is inverted (no poll except 3 known-bad models). **Reporting bounds are per cluster, from ZHA, not one shared triple** (`_POLLED_CLUSTERS` carries a `_ReportingBounds` per row, pinned by `test_the_bounds_asked_of_each_cluster_are_zhas`): OnOff `0/900/1` (a relay cannot chatter by itself; a floor only delays the answer to our own command), Metering summation `30/900/1` (it only ever grows, so "changed by 1" holds continuously — at 5 s that is a message every few seconds all print long), ActivePower `5/900/1`. `min_interval` is the floor between two **device reports**, not a poll interval. Battery sensors are never polled: `power_class` reads `node_desc.is_receiver_on_when_idle`, **not** `getattr(flags, "RxOnWhenIdle")`, which returns the always-truthy IntFlag member.

**Sensor reporting has three outcomes, not two.** `unanswered` (a sleeper that never woke — the usual case) ≠ `refused` (an explicit non-SUCCESS from the device) ≠ `ok`. Only a complete apply records the desired state; anything less is retried at the next contact, or one badly timed moment leaves a measurement unconfigured until re-pairing. Defaults live in `zigbee/measurements.py` (pinned by `test_the_defaults_are_the_agreed_ones`), taken from ZHA. `reportable_change` conversion branches on `raw_is_integer`: integer attributes floor at 1, floats must NOT — 1 ppm of CO2 is `0.000001` raw, and flooring it to 1 asks for a report every million ppm, i.e. silence forever.

**i18n.** Never hardcode user-facing strings. Frontend `useTranslation()`. Backend `t(lang, ns, "key.path")` + `escape_md()` for MarkdownV2. **en + uk only** — keys in BOTH.

**Drying while printing (opt-in, deny-by-default).** `supports_drying_while_printing(model, firmware)` in `printer_manager.py` gates the mid-print path against an explicit allowlist `_DRY_WHILE_PRINTING_MIN_FIRMWARE` (H2D 01.03+, H2D Pro/H2C/H2S/P2S 01.02+, X2D/A2L 01.01+, X1C 01.11.02+); every other model returns False. The gate only hides UI — firmware is the arbiter (rejects with `dry_sf_reason=[0]` TaskOccupied). **Never add a model without a Bambu wiki "Print While Drying" confirmation.** Mid-print drying temp is capped `max(40, preset - 5)` (`print_scheduler.py`) — never remove the floor.

**Server-side plate thumbnails (best-effort).** `services/plate_thumbnail.py` fills missing `Metadata/plate_N.png` in sliced 3MFs. **Any failure returns the input bytes unchanged — must never fail the slice.** Layered AFTER `library_3mf_preview.inject_source_stl_preview` (higher-fidelity plate 1 from STL); the checker skips plate 1 and only fills blanks (STEP/STP, preview-less 3MF, plates 2..N). Don't reorder the two passes.

**Filament attribution believes the DISPATCHED mapping, never the live one.** AMS filament backup swaps trays mid-print and rewrites the MQTT `mapping` field to the substitute, so read at completion it charges the whole print to the spool that only finished it. Priority in `usage_tracker._track_from_3mf`: stored print-cmd `ams_mapping` → queue item's `ams_mapping` → live `mapping` → colour match → `tray_now`. Both dispatched sources outrank the live one; don't reorder. Everything the split needs survives a restart in `active_print_sessions` (one row per printer, internal counterpart of `active_print_spoolman`, and the only carrier of `tray_change_log`) — written at start, appended by the `on_tray_change` callback chain, restored in `on_print_running_observed` **only** when its `print_name` matches what the printer is running, dropped at completion. Capture runs for BOTH inventory backends; `spoolman_owns_usage` only skips registering in `_active_sessions`, which doubles as on_ams_change's "skip the remain% weight sync" flag. ⚠️ A slot that empties mid-print is a RUNOUT — `on_ams_change` won't unlink its `SpoolAssignment` while the printer is `RUNNING`/`PAUSE` (read from printer state, not `_active_sessions`). ⚠️ Plate authority stays `PrintArchive.plate_index`; never copy it into the session row.

**Spoolman no-3MF tracking.** For "Untitled" prints with no `.gcode.3mf`, `spoolman_tracking.py` snapshots each AMS slot's `remain%` + `tray_uuid` at start (`_snapshot_tray_remain`) and writes consumed grams from the drop × curated reference weight — only for slots the 3MF didn't cover, skipping mid-print-swapped slots. Tracking rows store `filament_usage=[]` (not NULL) for this path; all readers use `filament_usage or []` — keep that contract.

## Branching & Release

- `main` — production; `kainpl/bamdude:latest` + `ghcr.io/kainpl/bamdude:latest` track it.
- `dev` — active dev; CI on push+PR. A push to `dev` publishes no image (the `Docker Build` CI job only builds and probes one); `:dev` moves with every pre-release tag.
- `feature/*` — short-lived; long-running upstream-port branches track `dev` via periodic merges.
- **Channels** (the whole procedure: `docs/release-guide.md`):
  - **Stable** `vX.Y.Z` on main → `:latest` + `:X.Y.Z`. `gh release create` after dev→main FF. **Docker publishes itself** — pushing a `v*` tag fires `docker-publish-tag.yml` (GHCR + Docker Hub, both arches), `windows-installer.yml` and `publish-code-graph.yml`; never also run the script.
  - **Beta** `vX.Y.ZbN` on dev → `:X.Y.ZbN` + `:dev` (no `:latest`).
  - **`:dev`** = the latest beta, moved by that tag (since 2026-08-18); `docker-publish-dev.yml` is a manual `workflow_dispatch` for the raw `dev` head only.
- **The CI gate is the run on `dev`, never the one on `main`.** `ci.yml` opens with `check-duplicate` (`fkirc/skip-duplicate-actions`) and every job hangs on `if: needs.check-duplicate.outputs.should_skip != 'true'`. A FF `dev` → `main` is the *same SHA on another ref*, so main's run skips every job and reports ✓ in ~10s having tested nothing. Order: push `dev` → `gh run watch --exit-status` on dev → FF `main` → tag. Skipping this shipped 0.5.1.2, whose dev run was red while main showed green.
- **Naming — one format, no exceptions.** Tag `v<version>`; release title `BamDude v<version>`, plus ` (pre-release)` when prerelease. No subtitles in the title — the body and CHANGELOG say what's in it. Drift check: `gh release list --limit 100 --json tagName,name,isPrerelease --jq '.[] | select(.name != ("BamDude " + .tagName + (if .isPrerelease then " (pre-release)" else "" end)))'` must print nothing. Titles are cosmetic — `gh release edit <tag> --title` touches no tag, image or asset, so fix in place, never re-release.
- **Tag immutability** — never force-push. Ship `X.Y.ZbN+1` or `X.Y.Z.1`.

- **Column** — model file (fresh installs) + `add_column()` in latest migration (existing DBs) + Pydantic schemas + frontend types.

- **Public frontend feature** — `npm run build` in verify; `static/` ships same commit.
- **Any of the above** — update the matching vault note in the same batch (see *Knowledge base*, rule 4). New subsystem → new note per `00-index/_design.md`; new invariant → `40-invariants/`. This is part of "done", not a follow-up.

## Upstream (Bambuddy)

BamDude is a hard fork of Bambuddy. Upstream releases are **adapted, not
merged**: the maintainer keeps a per-release audit in which every upstream
change is marked applied or rejected with a reason. When porting an upstream
change, first audit our own state around it — the two-tier queue (per-printer +
AutoQueue distributor), the dispatch claim per printer, the archive
chain-of-custody — and adapt the change onto that, never re-implement
upstream's flat model beside it.

## Bambu Studio reference

Bambu Studio is the protocol authority for Printer Settings, AMS Settings,
Filament Calibration, the `print.command="*"` dispatch mappings, gcode stage
strings and the canned calibration assets in `backend/app/data/calib_assets/`.
We mirror **protocol and assets only** — BS code is never merged. The
maintainer re-syncs the mirrored areas against each BS release.

### Mirrored printer configs (`backend/app/data/printers/`)

**Byte-for-byte** copies of BS `resources/printers/<code>.json` (one per model) — the data-driven source of truth for **per-model device capabilities** (`support_*_calibration`, `support_bed_leveling`, chamber, camera, …) so this knowledge lives in data, not hardcoded Python. Read by `utils/printer_configs.py` (`load_printer_config` + `device_calibration_availability` + the hybrid `resolve_device_calibrations`, which overrides the JSON base with the printer's live `support_*` MQTT flags). **Re-sync = re-copy the folder from a fresh BS checkout + `git diff`** (byte-identical unless BS changed a model) — full protocol in that folder's `README.md` (also records the source BS tag). Files are named by internal code (`N6.json`=X2D); the loader keys off each JSON's own `display_name`/`model_id`, **not** `PRINTER_MODEL_ID_MAP` (corrected in 0.4.7 to `C11`=P1P, `C12`=P1S per BS, with `BL-P001`=X1C/`BL-P002`=X1 added). Device calibrations run via one MQTT command `{"print":{"command":"calibration","option":<bitmask>}}` — bits: 0=lidar(xcam) 1=bed_leveling 2=vibration 3=motor_noise 4=nozzle_offset 5=high_temp_bed 6=clump_pos.
