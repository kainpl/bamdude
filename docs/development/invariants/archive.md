# Invariants: The print archive

Full text of the rules that [`CLAUDE.md`](../../../CLAUDE.md) keeps in short form, with the reasons and the history behind them. `Vault:` pointers name notes in the maintainer's private knowledge base; everything a contributor needs is here.

## The archive row is created at PRINT START, before the 3MF

(`on_print_start`, `file_path=""`), and the file is attached later via `attach_3mf_to_archive`. Time-sensitive start effects use that execution row: active-print tracking, energy baseline, notifications, queue ownership and timelapse setup. Spoolman tracking waits for the download outcome; an empty `file_path` deliberately selects its degraded remain%-delta path. Attach must fill the metadata that `archive_print` fills.

## Adoption identifies the physical execution before download

`on_print_running_observed` and `_adopt_running_print` use the current durable execution/claim decision. Downloaded bytes and their hashes do not select or merge executions. `_download_for_adopted_print` holds `archive_download_retry.claim` and the captured archive recovery identity, then attaches only to that incarnation. After successful attach, restore loaded-spool colours and objects into state; store Spoolman tracking after the download outcome even when no file could be attached. A print started while BamDude was down retains an unknown start until source estimates allow recovery from its stored observation, partial energy attribution, and a newly created usage session rather than replayed consumption. Adoption does not repeat start notifications, print-started macros, plate checks, plug actions or missing-spool prompts. The #1304 guard stays; only the current in-flight print is recoverable. Vault: `40-invariants/inv-print-memory-follows-observed-run.md`.

## 3MF download recovery

Empty `file_path` = the retry marker. `extra_data["no_3mf_available"]` means "we tried and failed" and is set ONLY after a failed attempt — it raises a user-facing banner, so never set it optimistically. `services/archive_download_retry.py` fills via 4 triggers: startup sweep, printer reconnect, `on_print_complete` last-chance, manual `POST /archives/{id}/retry-download`. ⚠️ `on_print_start` holds the same per-archive guard via `claim()` for its own download, or a mid-download reconnect attaches a second copy over the first. ⚠️ `ftp_timeout` bounds a **stalled** socket, not a slow transfer. Temp: `archive_dir/temp/<printer_id>/<filename>`. ⚠️ `services/archive.py::find_archive_for_sd_file` is the single «file name on the printer's card → archive» resolver (newest row with its 3MF OR its extracted PNG on disk — a retention-cleaned row keeps its picture by the 2026-09-12 ruling; pending and trashed rows never answer): the file manager's plates ask it, and nothing re-implements the match. ⚠️ **A running print's cover is its own archive, by id** (2026-09-30): `camera-cover` takes `routes/printers.resolve_current_archive_id` — the status's `current_archive_id` — and asks the name resolver only while that archive has nothing on disk yet (an external print's 3MF still downloading); only the own archive's picture is cached, or a fallback picture outlives the arrival of the print's own. A library job carries the library's file name into its archive while the printer echoes the upload name, so a name match can miss a print BamDude itself dispatched.

## An archive's folder comes from `utils/archive_paths.archive_dir_for` — never from `file_path` by hand

A row may legitimately have `file_path == ""` (created at print start, and a 3MF that could not be fetched never arrives — `extra_data["no_3mf_reason"]` says why; internal storage is NOT a reason, both storages are read on every printer that has both), and `(settings.base_dir / "").parent` is the PARENT of DATA_DIR — the timelapse and f3d writers did that until 2026-09-24 (upstream #2843): EACCES under Docker, a stray file beside the install elsewhere. Create the folder (`parents=True`) only after the filename passed `safe_join_under`. The fallback is `archive/no_source/<id>/` (`fallback_dir_for`) — NOT `archive/<id>/`, which is the printer folders' namespace (`archive/<printer_id>/…`) and held archive files until 2026-09-24 (audit D14). ⚠️ A photo's folder is not fixed: only its NAME is stored, and attaching a 3MF later moves the archive's folder — so photos are WRITTEN to `photos_dir_for` and READ / deleted through `find_photo`, which also looks in `no_source/<id>/photos` and the old `archive/<id>/photos`. `ArchiveService.delete_archive` removes those two id-owned folders; never `archive/<id>/` itself. `scripts/prune_orphan_archive_files.py` keeps every `*_path` column's file (read off the schema) and everything in a folder a row owns — mirror any new file location there. Vault: `40-invariants/inv-archive-folder-from-one-helper.md`.

## Archive chain-of-custody (m009+m039)

`source_content_hash` (SHA256 of unpatched root) + `content_hash` (SHA256 of FTP'd bytes) + `applied_patches` JSON. Invariant: every row has non-NULL `source_content_hash`. `effective_hash = COALESCE(source_content_hash, content_hash)` is disk-dedup key (cross-printer). Hard-delete ref-counts shared `file_path`s; `rmtree` only on last reference. Forensic queries use `content_hash` (distinct per applied-patch outcome).

## 3MF gcode patcher

`services/gcode_patcher.py::apply_3mf_transforms` comments `M970`/`M970.3` when `mesh_mode_fast_check=False` and applies gcode injection in ONE open/mutate/write cycle; recalcs `.gcode.md5` sidecars. (The single-purpose `patch_mesh_mode_fast_check` it superseded lost its last caller in that refactor and was deleted 2026-08-06.) **On-disk archive always unpatched** — patched copy → FTP via /tmp, dispatcher cleans up. `applied_patches` is informational; never read to infer disk state. `scripts/prune_orphan_archive_files.py` reconciles disk vs `print_archives.{file_path,thumbnail_path}` + `library_files`.

## 3MF copy is fsync'd

`archive.py::_copy_and_fsync` replaces `shutil.copy2` (sendfile silently truncated 3MFs on armv7l/bookworm — #1032). ZIP-validity check post-copy. Folder `YYYYMMDD_HHMMSS_<stem>` with `_2,_3` suffix on collision; `mkdir(parents=True)` no `exist_ok` so races fail loudly.

## Plate selection in 3MF parsing walks child metadata

Bambu identifies a plate with `<metadata key="index" value="N"/>` **inside** `<plate>`, NOT a `plate_idx` attribute. `ThreeMFParser` and `extract_printable_objects_from_3mf` must agree; a `.//plate[@plate_idx=…]` lookup silently misses and falls back to plate 1, which made `plate_number` inert for months and let Skip Objects cancel the wrong part on multi-plate jobs. Always pass the plate: `resolve_plate_id(client.state)` on live paths, `archive.plate_index` on archive paths.

## A print door asks the content, in one function (G11)

Whether a library file or an archive is a sliced print source is answered by `services/library_helpers.sliced_source_refusal` / `archive_source_refusal` for every door — the queue adds, the direct print, the dispatcher's `_require_sliced_source` and `_require_sliced_archive_source`, reprint: content KNOWN to hold no sliced G-code refuses whatever the name says (a project saved as `.gcode.3mf` used to reach the printer through direct print, dispatch and reprint); unknown content keeps the by-name rule; a stored "no" for a file on an external share is confirmed by one fresh read before it refuses (the file may have been sliced in place since the scan). A new door calls the function, never tests the extension. Vault: `40-invariants/inv-print-doors-ask-the-content.md`.

## An archive's printer and its running status are facts, not editable fields (G04, 2026-11-19)

`PATCH /archives/{id}` refuses a `printer_id` other than the current one (422), a hand-set `printing` (422) and any status change of a row that IS `printing` (409 — the live print owns it); internal writers (printer deletion's detach, restore) stay. A hand-set status moves the free-stock credit through the ledger's writer (`part_stock.follow_status_change`: leaving `completed` reverses what the archive still holds on the shelf, entering it credits as completion would; a refusal below zero never refuses the edit and is answered as `stock_not_followed`). There is no «auto-archive» setting: the archive is the print log and every physical print is one row — `printers.auto_archive` is a dead legacy column nothing reads (`test_every_print_is_archived.py`). New print work made FROM an archive (printer queue, AutoQueue, re-slice) asks what Reprint asks, in one function (`routes/archives.ensure_may_print_from_archive`). ⚠️ Upstream lends an earlier archive's 3MF to a printer-screen «Print again» by name, plate and layers — not ported: a name does not prove identity.

## A print's wear cost has one writer and is stamped only at a measured end (m246)

`services/wear_cost.py` alone assigns `print_archives.wear_cost` / `wear_rate` (guard test, callers pinned): at the two terminal writes of the live completion (`main._on_print_complete_impl`'s bound write and `ArchiveService.update_archive_status` when the row was still `printing`), for completed, failed and cancelled prints alike, duration = end − `started_at`. No figure — NULL, never 0 — for a print without a measured start (`started_at` missing or reconstructed), for a reconciliation close, an operator's close, an auto-repair or a cancel before start, and when the printer's record life no longer holds (the rate is read in the terminal transaction and `life_holds` asked right before the stamp). The rate applied is kept beside the figure; a changed rate never moves a stamped figure. An order's `total_cost` and `margin` include wear (`order_metrics`). Vault: `40-invariants/inv-wear-cost-one-writer.md`.

## «Result not checked» is a mark with one writer, never a verdict (m248)

`services/archive_outcome.py` alone writes `print_archives.outcome_checked_at` / `outcome_reminded_at` (guard test with a closed list of callers) and holds the one predicate (`is_unchecked` + its SQL twin `unchecked_clause`): completed, not trashed, not a calibration print, no mark. Fitness stays the DEFECT COUNT — upstream's Good / Reject was rejected (owner, 2026-11-17): `record_defects` marks the print on every write, an explicit zero included, and the «No defects» doors (`POST /archives/{id}/outcome-checked`, the Telegram button, a 👍 reaction) only set the mark and never touch the count; a 👎 opens the defects prompt and records nothing; a plate clear without a defects body marks nothing. A plate the swap changed by itself marks the print too (`mark_checked_by_swap`, called only by `swap_terminal`: our change_table answered success in `finish_change_table`, or `baked_clears` held for the file's own sequence — owner, 2026-11-20); a failed or held swap, an operator's manual SWAP settlement and a print our macro never ran for keep «Not checked», because somebody must go to that plate anyway; the live completion runs the macro before it writes the terminal status, so the badge never flashes. m251 marked the history's prints whose change_table claim is `finished`. m248 stamped every print existing at the upgrade as checked. The reminder (`print_outcome_unchecked`, off by default) is at most once per print: the sweep rides the notification service's minute loop, stamps by compare-and-set and commits BEFORE sending, whether or not anybody subscribes — so switching the event on releases no backlog. A link in a notification opens the list and records nothing. The Telegram message → archive map for reactions is in memory (bounded, lost on restart; the buttons still work) and compares the archive's immutable identity. A row taken back as a running print loses the mark (`dispatch_phase.forget_earlier_outcome`, which also clears the earlier failure reason). Vault: `40-invariants/inv-outcome-checked-is-a-mark-not-a-verdict.md`.
