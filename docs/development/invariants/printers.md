# Invariants: Printers, MQTT and the live print

Full text of the rules that [`CLAUDE.md`](../../../CLAUDE.md) keeps in short form, with the reasons and the history behind them. `Vault:` pointers name notes in the maintainer's private knowledge base; everything a contributor needs is here.

## Live layer counters belong to the observed print

`bambu_mqtt._update_state` computes the observed run boundary once before reading counters, clears only the old layer memory there, and keeps that frame's fresh values. A watched start without a total in that frame may use a status total received during its own pending PREPARE/SLICING window; never the cached old total or an ACK. A preparation status naming the old run blocks sparse totals until a status names a new run or terminal/idle closes the window; reconnect preserves this block. Terminal/idle, a changed pending run ID and an explicit preparation zero invalidate that candidate; same-lifecycle reconnect carries it. Only boundary frames read total before layer; ordinary/catch-up frames keep their order. A watched start and an id-only boundary deliver their first layer edge after the start callback; file-change-only frames suppress that edge while old timelapse/macro memory may remain. Neither boundary takes a finish photo. Vault: `40-invariants/inv-live-layers-belong-to-observed-print.md`. Live display may fill a missing total only from writer-stamped plate metadata addressed by an accepted start. `layer_projection` reads one completed immutable MQTT snapshot and an exact run/source grant, without I/O or TTL; an unproven file change advances only its projection revision. Display and effects dedup are separate. Never write the file total into `PrinterState` or physical/accounting effects. The sole text exception is an already-admitted first-layer notification: capture its addressed file pair before its branch awaits, recheck before send, otherwise keep the existing raw expression without skipping or replaying the event.

## Print memory and archive identity follow one observed run boundary

MQTT preserves an observed idle/terminal edge through PREPARE/SLICING until RUNNING, separately from process-fresh catch-up. A stable lineage and boundary generation survive same-lifecycle reconnects; a display alias never revokes a proven start. Missing/delayed firmware ids do not reuse the completed run's id or create a second start when the new id arrives. An unproven file change cannot reset print memory, teach a replacement id, or become a new run by DB comparison alone. Catch-up keeps its detector disarmed and journal held until its own recovery generation is seeded or abandoned, and reissues only on RUNNING/PAUSE; terminal frames cancel its pending callback without discarding the accounting journal. Preserve fail-armed runout seeding. Durable archive/dispatch identities decide adoption before INSERT, never downloaded hashes. Unaccepted dispatch attempts remain owned by their dispatcher even if it closes them during proof. Commit durability is a database fact; a committed but stale callback hands recovery to a current frame instead of binding or replaying effects. The first publication closes only proved noncurrent executions and their own claims without accounting or completion effects; late consumers carry the captured archive UUID. Vault: `40-invariants/inv-print-memory-follows-observed-run.md`.

## A command's acknowledgement is not the printer's status (upstream #3040, 2026-09-24)

The printer echoes a command's fields back on the report topic in the same `print` envelope as a status push, and every such frame runs through `_process_message` / `_update_state`. A field a command can carry as a REQUEST — the per-job `cfg` storage bit of `project_file` (`utils/timelapse.task_cfg`, which we send exactly as BambuStudio does, "4"/"0") and its `timelapse` — must be read only from a status frame: `bambu_mqtt.is_printer_status_frame` (`command` absent or `push_status`). Every `cfg` decoder (AMS settings bits, print options, print-option support) and the timelapse state go through it; read from the ack, our own "0" switched them all OFF after each dispatch and advertised "store sent files" on P1/A1, which send no `cfg` of their own. ⚠️ Not a blanket "ignore acks": the named `print_option` echoes are read on purpose as the confirmation of a set, and `_route_ack` / the dispatch capture need the ack. Vault: `40-invariants/inv-command-ack-is-not-status.md`.

## The crash-start pause belongs to the installation, not a printer connection

Only new print/calibration starts, automatic queue routing, automatic plug ON, drying and preheat consult `farm_startup_guard`. A reconnect never revokes the operator's global acknowledgement. Current-print controls, completion and swap macros retain the release lifecycle; do not add per-printer admission generations, command-publish gates or identity confirmation to this latch. Startup and restore failures remain visible and cannot be bypassed by deleting the durable marker. Vault: `40-invariants/inv-farm-startup-admission-is-durable.md`.

## A person's Stop is sent and marked in one place

Every door that stops a print — the printer card, a queue item's Stop, the webhook `stop` / `cancel`, the Telegram button, the HMS dialog's Stop Printing — goes through `services/print_control` (`stop_print_by_user`, `mark_hms_action`); `tests/unit/test_print_control.py` fails on any other call of `stop_print`. The mark (`main.mark_printer_stopped_by_user`) is what makes the completion handler read the printer's `failed` as `cancelled`; a door without it left the queue in error, announced a failed print and mailed the owner a failure. It is set in the same synchronous step as the send, before the caller's next await. ⚠️ A door never closes the queue row of a print the printer is running under our binding: the completion handler accepts a bound run's terminal only while its row is still `printing` (`main._accept_bound_terminal_run`) and closes row, archive and queue together — the queue item's Stop cancelled the row ahead of that report, the report was refused, and the archive stayed `printing` with the run bound until a restart (0.7.3). `POST /queue/{id}/stop` closes the row itself only when no run is bound for that archive (still being sent or heated — nothing on the printer owns it), whether or not the stop could be sent. With a bound run whose stop could NOT be sent it closes nothing and sets NO mark (nothing was stopped: a later real failure stays a failure, a real finish is a completed print with its filament booked — `mark_when_unsent` is passed only for a job with no bound run); it takes only the operator's pause (`is_paused`, never `status` — the queue still holds the printer) and answers 503 `{"error": "stop_not_sent"}`; the print is closed by the printer's report or by reconciliation on reconnect / restart (owner, 2026-11-19 — sending the operator to the System page for an ambiguity was the wrong cure). Vault: `40-invariants/inv-user-stop-has-one-door.md`.

## Macros

GCode via MQTT `gcode_line` wrapped with `M1002 gcode_claim_action:0/idle`. `services/macro_executor.py` + `PrinterManager.execute_macro_and_wait`. Swap macros fire by themselves: `swap_mode_start` from `background_dispatch` before `start_print`, `swap_mode_change_table` from `on_print_complete` (and `print_reconciliation`'s recovery). A model is swap-capable when a profile in `core/swap_profiles.py` names it — the printer form and the saved print profiles ask that catalog, never a list of their own; a new mod is a catalog entry plus its two built-in macros seeded by a NEW migration (m005, m192), whose G-code carries no `gcode_claim_action` of its own. `action_type='mqtt_action'` (m017+) routes via `core/mqtt_macro_actions.py` + `services/macro_trigger.py`.

## A deleted printer's runtime never passes to the next printer with its id (GH109 O1)

Before m262 SQLite handed the next row `max(id)+1`, so a re-added printer — and its first archive — could take the deleted ones' ids; a printer number is no longer handed out again (next section), but an archive id still can be, and a restored older copy brings its own counter back, so the record life stays. `PrinterManager` keeps a per-id record life (odd while a deletion runs; it moves only on a deletion and is never reset). `services/printer_deletion.py::begin` advances it and the client generation (advanced, never removed — an absent entry accepts every generation) before the delete's first await, and takes every id-keyed registry out of its container (`_ID_KEYED`: put back on failure, dropped on a confirmed commit); `finish` retires the old runs by the deletion's own effect boundary (`print_run_binding.retire_printer_runtime`). Nothing is removed by id after the commit, so a printer created with the reused id in between keeps what it registered. Work holding a `Printer` captures the life before its first await and proves it before connect, bind and publish (`PrintDispatchJob.printer_life`, `connect_printer(life=)`, `start_print(printer_life=)`). MQTT callbacks run through `_schedule_for_client` / `_run_for_client`: a queued callback of a deleted life is dropped at entry, and inside `session_scope` `get_client` / `get_status` refuse a deleted record's session, while a handler asks `session_still_lives` again after each await before it addresses the id. ⚠️ A check before a read proves nothing about the write after it: a writer that reads first calls `hold_record` — the printer's row, SQLite's writer or `FOR UPDATE` chosen by the session's own connection, conflicting with the deletion's `lock_sensor_target`, which the deletion takes only after the life has changed — and proves the life under that lock before it writes; memory is published after a commit only on a synchronous proof with no await before the set. The reconcile closer proves life and row identity under its archive lock, then rechecks life after accounting/session-cleanup awaits and its own commit. Accounting may roll back and expire the ORM row: a lost life exits before reading it again, and final analysis cleanup uses captured IDs plus the original archive UUID. A failed, refused or cancelled delete, or a commit whose outcome is unknown, keeps the binding for the manual GH109 recovery; there is no new 409 during dispatch (owner's D1). An ordinary reconnect changes no record life. ⚠️ `_ID_KEYED` lists only containers keyed by the PRINTER — `main._print_ams_mappings` is keyed by archive id and, listed there, dropped the mapping of whichever archive shared the deleted printer's number. Files named by the id (plate-detection references) are removed in `finish(committed=True)`, synchronously; a reader that awaits re-reads its per-printer state with `.get` afterwards (Obico) instead of indexing it. Vault: `40-invariants/inv-deleted-printer-runtime-not-inherited.md`.

## A printer number is never handed out again (P-ID, m262)

The process keeps far too many dicts and sets keyed by printer number to clear them one by one on a delete (`printer_deletion._ID_KEYED` covered a fraction; GH109 was a deleted printer's "current print" blocking the next printer's first dispatch). So the cause is removed instead, as C047 did for spools: `Printer` carries `sqlite_autoincrement`, and m262 rebuilds an existing SQLite table through `_sqlite_autoincrement.ensure_autoincrement` (it owns `BEGIN IMMEDIATE` and `PRAGMA foreign_keys`). State left under a deleted number becomes an orphan, never another printer's state.

The counter starts above every number a current reader could still pick up, not only `MAX(printers.id)`: `core/printer_id_bound.py` is a registry FROZEN at the schema P-ID met — the printer's own queue (`printer_queues.id` is the printer's number), every column with a foreign key to `printers.id` or `printer_queues.id`, the integer columns kept without one, the positional AMS key `p{printer}a{ams}` of `ams_labels`, an API key's `printer_ids` read exactly as the gate iterates and `int()`s it, an order's `printer_resources`, the targets of order working plans (`entries`, `saved_entries`) and of plan submissions, the `default_printer_id` / VP-target / Obico settings, and the historical columns an old file still has. It is not derived from the models: the migration and the import read older levels. A carrier added later needs no entry — its numbers come from a counter that already never goes back — and the guard (`test_printer_id_bound.py`) makes such an FK say so. A value's own SQLite class decides, not the declared type; on PostgreSQL an integer carrier of another type stops the migration. A carrier that a level's applied migration guarantees and that is missing stops it — a historical one only until the migration that removed it is applied; one only `create_all` makes may be absent. A setting's row is optional, but a present `settings` table without `key` and a text `value` stops it too.

The domain is 1..2³¹ − 1 (PostgreSQL `integer`, exact in JavaScript): a value outside it is not reserved, and with no number left at or below 2³¹ − 1 — the registry, `MAX(printers.id)` and `sqlite_sequence` on SQLite; the sequence's own `next_value` against `min(seqmax, 2³¹ − 1)` on PostgreSQL, with or without carriers — the migration stops before its commit and writes no marker. SQLite has no allocation ceiling and P-ID sets none: numbers above the domain are outside the guarantee (owner). The SQLite→PostgreSQL import takes the same bound from the prepared snapshot before the FK repair, joined with the file's counter even when the file already has m262; the portable export carries the counter by the model flag; a SQLite ZIP copies `sqlite_sequence`. Outside the guarantee: an explicit id, a manual sequence reset, restoring an older or another line of data (it brings its own counter back; the process restarts, so memory is not inherited), references old converters removed before m262, and the Telegram-chat and notification-provider scopes, which stay outside the registry (on a farm every printer and chat is the operator's own). Vault: `40-invariants/inv-printer-number-never-reissued.md`.

## Archived printers (soft-retire, m105)

`Printer.archived` + `archived_at` — an INDEPENDENT axis from `is_active` (Maintenance Mode): maintenance parks temporarily + keeps the card visible; archive retires + hides everywhere, history preserved. "Available" = `is_active AND NOT archived` — the `Printer.archived.is_(False)` filter sits beside **every** `is_active==True` availability query (MQTT connect loop, scheduler, `auto_queue_eligibility.find_eligible_printer`, metrics, pipelines, VP, telegram, …) **and** the queue-list endpoint (`printer_queues.list_queues`). `GET /printers/` excludes archived unless `?include_archived`; keep the frontend `getPrinters()` **param-free** (a separate `getPrintersWithArchived()` feeds the restore section + Archives filter — an optional arg breaks TanStack's `queryFn: api.getPrinters` inference). `POST /printers/{id}/archive` (PRINTERS_DELETE) blocks while `is_print_active` (409), cancels the printer's pending `print_queue` items, disconnects MQTT. Restore/delete under Settings → Printing → Archived printers.

## Manual jog mirrors BambuStudio, never disables endstops

`bed_jog` emits BS's own sequence byte-for-byte (`../references/BambuStudio/src/slic3r/GUI/DeviceCore/DevAxisCtrl.cpp:49`): `M211 S` → `M211 X1 Y1 Z1` → `M1002 push_ref_mode` → `G91`/`G1` → `M1002 pop_ref_mode` → `M211 R`. **Never emit `M211 S0`** — that form doesn't exist in Bambu's dialect (bare `M211 S` is *push*, `M211 R` is *pop*), and Bambu's own sliced start G-code leaves the soft endstops OFF, which is why BS re-enables them before every jog. There is deliberately no trailing `G90` (pop_ref_mode restores it) and no `force` param. The not-homed modal stays — but ⚠️ **not because BS refuses an unhomed jog; it does not.** `StatusPanel::check_axis_z_at_home` is called *after* `Ctrl_Axis` has already published, so BS sends the Z move and then pops a recenter dialog. Our modal is a deliberate divergence (an HTTP surface reachable from another room is not a desktop window in front of the machine), and #2579 removed "Move anyway" because it drove the move with the soft endstops disabled. Don't "restore parity" here. The #1334 bed-slinger Z-sign flip is safety-critical — BS corroborates it at `DevAxisCtrl.cpp:39-44`; the flip lives ONLY in `move_axis`, and kinematics come from the mirrored config (`printer_arch`), with alternate internal codes (`A11`/`A12`/`A04`) resolved through `PRINTER_MODEL_ID_MAP` — an unresolved code defaults to CoreXY, i.e. NO flip. ⚠️ Two sign conventions, one route each (audit D11, 2026-09-24): `/jog` (card + Motion window) takes BS's ARROW value ("negative = the part on Z goes up"); `/bed-jog` takes a model-independent GAP ("positive = more room", via `move_nozzle_bed_gap`, which pre-flips so `move_axis`'s flip cancels). They are opposite on an i3 machine. `PrinterStatus.is_bed_slinger` exists for WORDING ("Z"/"toolhead") and must never flip a sign in the frontend.

## H2C: the rack is extruder 0, and a rack position is the operator's (upstream 45dc139c, 3954d3a7)

On a nozzle-rack model (`is_nozzle_rack_model`) the rack carriage is MQTT extruder 0 (BambuStudio's MAIN, right) and the fixed hotend extruder 1 — `bambu_mqtt._RACK_EXTRUDER_ID` / `_FIXED_EXTRUDER_ID`, `printer_models.NOZZLE_RACK_EXTRUDER_INDEX`. On the wire the fixed hotend is physical id 1 and the rack carriage is a dock 16–21 (position R*n* = 15 + *n*), never 0: an extruder index never reaches `nozzle_mapping` untranslated, and swapping the two carriages levels with one nozzle and prints with the other, millimetres above the bed. Which dock each filament GROUP prints from is stated nowhere in the 3MF, so `background_dispatch._rack_dispatch` resolves it after the upload and before preheat: the file's rack plan (`threemf_tools.extract_rack_plan_from_3mf`; the rack is the slicer extruder whose `extruder_max_nozzle_count` > 1) plus the operator's pick (`print_queue.nozzle_rack_choice`, m187 — a direct print carries it in `ReprintRequest` / `FilePrintRequest`, because it is not a queue row) through `bambu_mqtt.resolve_rack_plan_mapping`. ⚠️ An EXPLICIT pick the live rack no longer fits refuses the print and deletes the uploaded file from the card; an automatic assignment that fails falls back to the #2800 path (the live dock; no `nozzle_mapping` at all for a plate needing two rack hotends — `_plate_needs_several_rack_nozzles`, asked on the dispatch path only, because routing, the archive and the library still need each slot's carriage). A Virtual Printer capture's `nozzle_mapping` outranks all of it — and is therefore kept only for the printer the slicer read it off: `VirtualPrinterInstance.keeps_slicer_nozzle_mapping` drops it on a rack model unless the job prints on the VP's own target (no target, the auto-queue tier and a fallback printer drop it), and a job moved to another queue or into AutoQueue leaves it behind (`print_queue._drop_rack_pick_on_move`, `queue_auto_transfer`). Vault: `40-invariants/inv-h2c-rack-is-extruder-0.md`, `60-specs/h2c-nozzle-rack-dispatch.md`.

## Preheat / heat-soak stage (opt-in, #1468)

Between FTP upload and `start_print`, `services/preheat.py::preheat_and_soak` (invoked from `background_dispatch` in both `_run_*` branches) heats bed + chamber and holds at temp — firmware ignores `M191`, so the soak is orchestrated here. Per-print chamber target = max via `DEFAULT_PREHEAT_FILAMENT_TARGETS` across the feeds the job's `ams_mapping` names (the routing plan's, in `job.options`), read off the feed snapshot so an advertised slot counts as its real spool and a named external feed counts too — never the whole AMS when the print says which trays it uses (upstream #2886: one parked ASA put 45 °C in front of every PLA job); with no usable mapping, every AMS slot (a type with no row of its own takes its base's: ASA-GF → ASA). ⚠️ A 0 DERIVED from the filament map skips the whole stage (upstream #3041, audit D8 — once documented as intended, ruled a defect 2026-09-25): no bed, no soak, only `_flap_to_cooling` on airduct models; an explicit per-item 0 ("bed + soak, no chamber") and a per-item `on` still run bed + soak, and the print options say so under the target field; three hardware tiers gated by `supports_chamber_heater` / `supports_airduct` (active `M141` / sensor-wait / timer) with airduct-flap flip. Per-print override in `PrintQueueItem.preheat_override` (+ `preheat_chamber_target_override`) threaded via `job.options`. Cancel-aware. Off by default (`preheat_enabled`). ⚠️ Both wait loops re-send the setpoints every 60 s, alternating target / target − 1 °C, through the client looked up at each send, and the stage ends on the exact targets: an idle X2D drops a setpoint 300 s after it last CHANGED, and a repeat of the same value does not restart that timer (hardware capture, PR #114).

## Drying while printing (opt-in, deny-by-default)

`supports_drying_while_printing(model, firmware)` in `printer_manager.py` gates the mid-print path against an explicit allowlist `_DRY_WHILE_PRINTING_MIN_FIRMWARE` (H2D 01.03+, H2D Pro/H2C/H2S/P2S 01.02+, X2D/A2L 01.01+, X1C 01.11.02+); every other model returns False. The gate only hides UI — firmware is the arbiter (rejects with `dry_sf_reason=[0]` TaskOccupied). **Never add a model without a Bambu wiki "Print While Drying" confirmation.** Mid-print drying temp is capped `max(40, preset - 5)` (`print_scheduler.py`) — never remove the floor.

## Scheduled drying has one writer, yields to every print and holds its own unit (m184)

`services/scheduled_drying.py` is the ONLY writer of `drying_schedules` (recurring rules) and `scheduled_dryings` (runs); routes read, and a printer's archive / delete goes through its `forget_printer` (SQLite runs no FK actions). A rule's `start_time` / `latest_start` is wall-clock in the SERVER's zone (`core/timezones.server_timezone()`), a run stores naive UTC, and windows that closed while the server was down are skipped silently. `PrintScheduler._tick_scheduled_drying` runs `tick()` every pass, in its own session, BEFORE `_check_auto_drying`, and never lets a failure reach the queue. ⚠️ `_drying_in_progress` is SHARED with auto-drying: auto-drying never arms a unit in `_scheduled_dry_units`, and releases a hold only through `_release_drying_hold`, which leaves a printer with a running scheduled cycle alone (it may be cooling with `dry_time == 0`); the tick drops that hold itself once nothing dries there, and `_seed_scheduled_drying_holds` restores it after a restart before the first dispatch. ⚠️ A scheduled cycle yields to a print on EVERY model, dry-while-printing ones included (its temperature is the operator's, not the mid-print cap): `preempt_for_print` at the dispatch point (own session) AND `_follow` for a print that came some other way — Print now, the printer's screen, the slicer — both through `_yield_to_print`. ⚠️ An empty printer state is not a state: a client exists before its first report and after every reconnect, so an offline or unreported printer / unit is waited for, never judged (no "firmware cannot dry", no silent cancel). A cycle the unit never showed running within `START_CONFIRM_SECONDS` is `not_started` and reported. Vault: `40-invariants/inv-scheduled-drying-yields-and-holds.md`.

## VP nozzle authority follows the target binding

VP nozzle authority follows the target binding, never bridge connectivity. Bound instances pass through real nozzle data or explicitly report unknown while cold; unbound instances advertise the saved main-nozzle pair without flow capability bits or invented dual/rack topology. Pair changes are hot updates; deleting a printer explicitly detaches VP targets before its id can be reused. Queue selection skips only positively mismatched diameters and does not replace final dispatch checks. Vault: `40-invariants/inv-vp-nozzle-follows-binding.md`.

## VP FTP needs the asyncio loop

`uvicorn[standard]` auto-selects uvloop, whose TLS layer can silently truncate a 3MF uploaded to the virtual printer on a ragged EOF (#1896). **Every native launch path passes `--loop asyncio`** (Dockerfile, `install/install.sh` systemd+launchd, `deploy/bamdude.service`, Windows NSSM/`install-service.bat`) — never drop it. Defense-in-depth: `virtual_printer/ftp_server.py::cmd_STOR` ZIP-validates a `.3mf` before ACKing (426 on truncation, no fallback archive of a broken job).

## The next slicer pause is read from the print's own file and compared with the proven run's layer (G12)

Pause points (`M400 U1` with the layer and, when present, the `M73 R` marker) come from the same single pass over the plate's G-code as the usage analysis, of the archive's UNPATCHED file, kept in the print-file analysis (no column); the analysis starts when the source is bound. `pause_forecast` compares only the layer of the proven observed run (`LayerSnapshot` + a current grant) — never `state.layer_num`, never an ACK — and gives minutes only at Standard speed with time markers; by-object files, an unknown total, a missing file or an unproven run give nothing rather than a guess. `next_pause` goes through both status shapers and `live_projection.STATUS_FIELDS`. The event `pause_coming_up` is one catalogue row, off by default everywhere, fired once per (archive recovery identity, pause layer) — never keyed by `subtask_id` or a printer id; after a restart inside the lead window one warning may be skipped, none is repeated. It sends no command and changes no dispatch. Vault: `40-invariants/inv-next-pause-from-the-file-and-proven-run.md`.

## Obico AI failure detection (opt-in)

`services/obico_detection.py` polls RUNNING printers every 5–120s. JPEG cached under 32-byte nonce (30s TTL); Obico ML gets URL to `/api/v1/obico/cached-frame/{nonce}` (whitelisted in `auth_middleware`). The verdict is Obico's own `is_failing` (`obico_smoothing.py`, a port of obico-server `lib/prediction.py`, compared with it frame by frame in `test_obico_smoothing.py`): score = EWM − the PRINTER's long-term mean (`_baselines`, memory only, carried across prints), `warning` = Obico's alert, `failure` = its pause (score ÷ 1.75) — never compare a raw EWM or a `max(...)` with the thresholds again (upstream #3459: the camera's constant background ended in "failure"). A print's state lives from its first frame to `_ENDED_STATES`, a new task name, another execution archive or — with no bound run — another job id; PAUSE and a reconnect keep it, so each action runs once per print. The alert notifies whatever the action; pause / pause_and_off (MQTT, +smart-plug) wait for `failure`; a failure still suspected `REMIND_AFTER` (3 h) after the print's last notification is notified again, never paused again. The ML API fetches the frame from `obico_snapshot_base_url` when set, else `external_url` — our own address, not a destination we request.

## One AI failure detector at a time; a restore never turns OctoEverywhere on

OctoEverywhere (`services/octoeverywhere_detection.py`) is ported from upstream Bambuddy v1.3.0 and works beside Obico the way upstream's does. Two flags, `obico_enabled` and `octoeverywhere_enabled`: `PUT /settings` refuses both on in one body (400) and switches the other off when one is turned on; because a restore can write the rows without that route, Obico's `_load_settings` is also off while `octoeverywhere_enabled` is on, and OctoEverywhere's while `obico_enabled` is on — never both acting.

OctoEverywhere keeps a Gadget context per print and acts on the API's `WarningSuggested` / `PauseSuggested`; `PrintQuality` (1-10) is shown, never thresholded. Pacing is the configured 5–30 s interval, never below the server's `Minimum`. A warning notifies once and is told again after three hours; a suggested pause runs the configured action once per print, through Obico's `execute_action` (`octoeverywhere_actions.py`). The print's state ends on `FINISH` / `FAILED` / `IDLE`, in `on_print_start` and `on_print_complete`, and when two job ids differ. Its frames come through the camera worker by Obico's rule — a watched live view lends its buffered frame, an empty one skips the inspection, never a second camera handle — and no inspection starts while the worker is unavailable. The key is a write-only credential (`SETTINGS_SECRETS`), sent only in `X-API-Key` to `CREATE_CONTEXT_URL` or a process address that passes `_process_url`; exception text never reaches a log or a status.

A full ZIP restore whose database had OctoEverywhere on restores it off (in the prepared copy, so on PostgreSQL inside the restore's transaction) with a private `_bamdude.` marker; the first start tells every active administrator in the inbox, whatever their subscriptions, in the transaction that consumes the marker. The SQLite → PostgreSQL move keeps the setting; a Git restore never writes `octoeverywhere_enabled`. The restore waits for `octoeverywhere_detection_service.quiesce()` as it does for Obico. Vault: `40-invariants/inv-one-failure-detector-at-a-time.md`.

## Obico evidence is an observation, not a new camera capture or print authority

The opt-in bounded recorder owns immutable analysed JPEG bytes and validated server-returned center tuples; display projection never guesses the ML backend or corrects upstream height scaling. Images use the encoded JPEG grid without EXIF rotation, and buffer arrival is not exposure time. One store owns publication, quotas and deletion. Reference-based backup pins protect originals without pausing recording; logical deletion commits first, then pin check and actual unlink share one guard until owned I/O finishes. Printer deletion uses short store barriers, never holds that guard across archive/task/VP work and never waits for backup copying; restore separately drains its owner.
